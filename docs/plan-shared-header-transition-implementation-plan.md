# 计划页头部与共享元素折叠实施计划

## 实施原则

- 按已确认的《计划页头部与共享元素折叠规格》实施，不扩大到动作表单和训练业务。
- 新建计划页专用过渡组件，复用今日页、我的页面的测量模式，但不修改它们已经稳定的行为。
- 先完成结构与状态，再接入共享元素测量，最后处理响应式和降级，避免样式与动画同时失控。
- 动画视觉效果由用户本地体验确认；代码侧完成类型、Lint、构建、测试和逻辑检查。

## 涉及文件

### 新增

- `components/plan-shared-transition.tsx`
  - 负责计划图标、“周计划”和训练日名称的共享元素测量与滚动插值；当前星期只由固定星期栏表达。
  - 负责折叠阈值、固定状态切换和减少动态效果降级。
- `docs/plan-shared-header-transition-implementation-plan.md`
  - 本实施计划。

### 修改

- `components/training-plan-view.tsx`
  - 重构计划页头部结构。
  - 增加固定目标栏、移动端压缩周切换和共享元素引用。
  - 增加星期切换方向及固定状态的可访问性控制。
- `app/page.tsx`
  - 向计划页传入 `.app-content` 滚动容器引用。
  - 切换模块时重置计划页折叠变量和状态标记。
- `app/globals.css`
  - 新增计划头部、固定区、共享层及响应式样式。
  - 删除或覆盖现有英文标题、大图标、重复边框及移动端横向周列表样式。
  - 增加 `prefers-reduced-motion` 规则。

## 阶段 1：建立头部信息结构

### `TrainingPlanView` 属性

为组件增加：

```ts
scrollerRef: RefObject<HTMLDivElement | null>
```

由 `app/page.tsx` 传入现有 `appContentRef`，保证滚动坐标仍以真实内容容器为准。

### 展开头部

将现有：

- `WEEKLY PROGRAM`
- “安排你的一周”
- 原副文案
- 右侧 `52px` 孤立计划图标

替换为：

1. 身份行：计划图标、“周计划”、训练日数量、同步状态。
2. 主标题：“安排你的一周”。
3. 副文案：“安排训练日和动作，保存后同步到今日训练。”

头部不再继承通用 `.page-header` 的底部分割线视觉，使用计划页独立类名控制留白。

### 状态文案

从现有状态直接派生，不新增业务状态：

- `saving === true`：`正在保存`
- `dirty === true`：`未保存`
- 其他：`已同步`
- 训练日数量：`draft.days.filter(day => day.enabled).length`

## 阶段 2：建立固定目标与双层移动端结构

### 固定外壳

在计划页根节点内、展开头部之前增加：

```text
plan-compact-shell
├── plan-compact-context
└── plan-compact-weekdays
```

外壳采用 `position: sticky; top: 0; height: 0`，不参与正文滚动高度。

### 第一层目标

预留以下测量目标：

- 图标目标
- “周计划”目标
- 当前训练日名称目标
- 保存状态目标

目标元素只用于布局测量并保持 `visibility: hidden`；真正的共享视觉由固定层绘制。保存状态不是主共享元素，可以直接在固定层按进度显示。

### 第二层星期切换

- 移动端渲染七个等分按钮，只显示 `一 二 三 四 五 六 日`。
- 桌面端通过媒体查询隐藏，不复制顶部星期栏。
- 通过 `condensed` 布尔状态切换可交互性：
  - 未折叠：`aria-hidden="true"`，按钮 `tabIndex={-1}`，`pointer-events: none`。
  - 已折叠：恢复可访问与点击。
- 原周导航在折叠后停止接受键盘焦点；移动端视觉上已经滚出固定区，桌面端仍保留左侧导航。
- 不在滚动每一帧触发 React 更新，只在跨过折叠阈值时更新一次 `condensed`。

## 阶段 3：实现 `PlanSharedTransition`

### 输入引用

组件接收：

- `scrollerRef`
- 展开态图标、“周计划”、训练日名称的 source refs
- 固定栏对应 target refs
- `selectedWeekday`、`selectedDay.name`
- 当前保存状态
- `onCondensedChange`

### 测量策略

沿用现有共享元素组件的可靠模式：

1. 查找最近的 `.kinetic-page-stage`。
2. 页面切换尚未完成时保留真实 source，隐藏共享层。
3. 收到 `kinetic-page-transition-complete` 或检测页面 transform 已归位后再测量。
4. 暂时把 `--plan-header-collapse` 设为 `0`，读取 source 和 target 的标准坐标。
5. 恢复原进度并调用一次 `update()`。
6. 使用 `ResizeObserver` 监听滚动容器、source 和 target；字体加载、窗口尺寸改变后重新测量。

### 插值内容

- 图标：`translate3d + scale`。
- “周计划”：插值 `left / top / font-size / line-height / font-weight`，不整体缩放文字。
- 训练日名称单独插值位置、字号、行高、字重，最终在目标行组成 `周计划　全身 A`；第一行不渲染星期和分隔点。
- 共享层 `pointer-events: none`，不阻止下方编辑操作。
- 固定背景和非共享内容通过 `--plan-header-collapse` 驱动透明度与少量纵向位移。

### 源元素交接

- 折叠进度为 `0` 时显示真实 source，确保训练日名称输入框可正常点击、选择和编辑。
- 进入迁移阶段后，在同一坐标显示共享视觉层，再隐藏 source 的可见内容；不采用两套内容同时交叉淡入。
- 反向滚动回到起点时恢复真实 source。
- 如果训练日名称输入框仍处于焦点，数据输入继续写入 draft，共享层文本跟随 React 属性更新；回到顶部后恢复原输入框视觉。

### 滚动阶段

- 折叠距离：移动端先以 `148px`、桌面端以 `156px` 为初始实现值，最终只按布局逻辑微调。
- `0–0.08`：保持。
- `0.08–0.48`：图标与“周计划”迁移，原周导航退出，压缩星期栏完成固定。
- 当训练名称中线与固定区底边相交时：只把训练名称迁移到固定栏；当前星期继续由第二行的固定周导航表达。
- 第二阶段使用独立的 `--plan-context-collapse`，移动端跨约 `80px`、桌面端跨约 `88px` 完成，不与第一阶段的总折叠比例绑定。
- `>= 0.72`：设置 `data-plan-header-condensed="true"` 并通知 `onCondensedChange(true)`。
- `0.76–1`：锁定目标位置。

进度直接跟随滚动，不使用 spring、setTimeout 或滚动停止后的补间。

## 阶段 4：星期切换与内容方向

### 统一切换入口

新增 `selectWeekday(nextWeekday)`，替换两套星期按钮直接调用 `setSelectedWeekday`：

1. 根据新旧 weekday 判断方向。
2. 更新 `selectedWeekday`。
3. 让动作编辑内容按方向进入。
4. 更新共享层内容并重新测量目标文字宽度。

### 方向规则

- 从较小 weekday 切到较大 weekday：内容从右侧进入。
- 从较大 weekday 切到较小 weekday：内容从左侧进入。
- 不按一周首尾循环距离做特殊判断，保证顺序可预测。
- 位移控制在 `12–16px`，时长约 `180–220ms`，使用 `ease-out-quart` 或现有 `[0.16, 1, 0.3, 1]`。

### 防误触

- 固定星期栏使用等分布局，不产生横向滚动，因此保留页面纵向 `pan-y`。
- 在指针按下时记录起点；移动距离超过约 `8px` 后，本次释放不执行星期切换。
- 只为固定星期栏添加轻量拖动保护，不改全局按钮行为。

## 阶段 5：响应式样式

### 移动端 `<= 760px`

- 计划页水平内边距与现有内容保持一致。
- 展开头部控制在约 `132–148px`，减少截图中顶部空洞。
- 固定上下文栏约 `52px`，压缩星期栏约 `42px`。
- 渐隐背景覆盖固定区及其下方约 `14px`，样式与“我的”页面一致。
- 原 `.week-rail` 从横向 `92px` 卡片列表改为紧凑七等分展开导航，不再依赖横向滚动。
- 固定区不改变 `.app-content` 高度，不给页面底部增加额外 padding。
- 保存栏继续在底部导航上方，按钮保持居中。

### 桌面端

- 头部使用新的身份行、标题和说明。
- 保留 `220px` 左侧周导航及右侧动作编辑结构。
- 固定区只有第一层，约 `56px`；移动端压缩星期栏隐藏。
- 左侧导航减少无意义横线，但仍保留选中轨迹和训练日状态。

### 视觉细节

- 删除通用头部边线和 `plan-workspace` 顶部重复边线。
- 周导航项之间使用留白和低强调轨迹，不为每项绘制完整分割框。
- 训练日为亮绿色状态，未保存为橙色；不增加新的状态颜色。
- 固定背景使用渐隐，不使用纯色矩形或额外圆角卡片。

## 阶段 6：页面切换与清理

在 `app/page.tsx` 的 view 切换重置逻辑中增加：

```ts
--plan-header-collapse: 0
data-plan-header-condensed: false
```

同时保证：

- 进入计划页先回到顶部，再测量展开态。
- 离开计划页时共享层立即隐藏，不停留在其他模块上方。
- 页面切换中的横向位移动画结束前不启动共享元素，避免图标和文字二次位移。
- 组件卸载时取消 `requestAnimationFrame`、事件监听和 `ResizeObserver`。

## 阶段 7：验证

### 自动验证

按顺序执行：

1. `git diff --check`
2. `npx tsc --noEmit`
3. `npm run lint`
4. `npm test`

如果 `npm test` 已包含生产构建，则不重复运行；否则补充 `npm run build`。

### 代码逻辑检查

- source 与 target 引用在移动端、桌面端都存在。
- 页面切换期间不会提前测量错误坐标。
- 星期切换只在阈值变化时引起 React 状态更新，不在滚动每帧 setState。
- 训练日名称编辑后，共享层和固定栏不会保留旧值。
- `dirty / saving / synced` 状态不会出现颜色与文案不一致。
- 组件卸载后 CSS 变量、dataset、source visibility 全部恢复。
- 固定星期栏不可见时不进入键盘焦点顺序。
- `prefers-reduced-motion` 下无连续位移，但所有星期切换和编辑功能可用。

### 用户视觉验收

按用户之前确认的协作方式，不额外进行耗时的自动截图对比；启动本地服务后由用户重点检查：

1. 首次进入计划页时图标和文字跟随整页进入，没有单独动画。
2. 上下滚动时计划图标、“周计划”和当前训练日连续落入固定栏。
3. 文字在字号、字重变化过程中保持清晰。
4. 固定背景不会和下方表单文字叠在一起。
5. 固定星期栏切换方向正确，拖动页面不会误触。
6. 移动端底部没有额外空白，保存按钮与底部导航不互相遮挡。

## 风险与控制

### 1. 输入框与共享文字交接

风险：训练日名称是可编辑输入框，直接永久隐藏会影响编辑。

控制：只在滚动进入迁移阶段后交给共享视觉层；起点状态保留真实输入框，焦点与数据始终留在原控件。

### 2. 页面切换坐标错误

风险：计划页整体仍在横向进入时测量，会让图标和文字产生一次额外位移。

控制：等待 `kinetic-page-transition-complete`，并保留现有 transform 归位兜底检测。

### 3. 两套星期按钮重复交互

风险：展开导航和固定导航同时可点击或同时进入无障碍焦点。

控制：用单一 `condensed` 阈值切换 `pointer-events`、`aria-hidden` 和 `tabIndex`，不依赖透明度判断。

### 4. 固定区造成底部空白

风险：错误设置占位高度会重复计算固定栏，出现此前移动端大空白问题。

控制：固定外壳保持 `height: 0`，正文不添加等高 padding；只在视觉层覆盖顶部。

### 5. 滚动性能

风险：每帧测量布局、更新 React 状态或动画文字 transform 会造成顿挫。

控制：测量与更新分离；滚动帧只写样式，文字插值使用定位值，React 状态只在阈值变化时更新。
