# “近期训练”游标分页与轨迹续接动画规格

> 实施计划见
> [`profile-recent-workouts-pagination-motion-implementation-plan.md`](./profile-recent-workouts-pagination-motion-implementation-plan.md)。

## 文档关系

本规格扩展已确认的 [`profile-recent-workouts-redesign-spec.md`](./profile-recent-workouts-redesign-spec.md)。

原规格中的三列账页布局、时间线、绿／橙／蓝循环、长名称对齐和 `0 kg` 展示规则继续有效。本规格仅覆盖以下新增能力：

- 默认只返回并展示最近 6 次已完成训练。
- 点击后按游标每次加载 20 条更早记录。
- 记录超过容器高度后只在“近期训练”内部滚动，不继续撑高页面。
- 为加载中、加载完成、加载失败和到达最早记录增加“轨迹续接”状态与动画。
- 避免训练记录增多后，仪表盘为了近期列表读取全部训练明细。

如两份规格存在冲突，以本规格中的分页、滚动和动画规则为准。

## 背景

当前“近期训练”最多展示服务端返回的 20 条记录，但服务端会先查询用户全部训练及训练组，再在内存中截取前 20 条。随着训练历史持续增长，会出现以下问题：

- 页面无法继续查看第 20 条之后的记录。
- 仪表盘仍然读取全部训练明细，数据量大时查询、聚合和内存开销持续增长。
- 如果直接把更多记录追加到当前页面，近期训练会不断把力量趋势向下推。
- 加载更多记录时缺少明确、与品牌一致的状态反馈。

本次把“近期训练”改为有固定视觉窗口的历史轨迹，并使用稳定的游标分页读取更早记录。

## 目标

1. 用户首次进入“我的”时，可以立即看到最近 6 次已完成训练。
2. 用户每次点击“加载更早记录”，获取 20 条更早的已完成训练。
3. 记录增多后，近期训练模块高度保持稳定，只在模块内部纵向滚动。
4. 加载过程清楚表达“正在继续读取更早轨迹”，不使用普通旋转菊花。
5. 新记录进入时有一次短促、流畅的品牌动画，不导致滚动跳跃。
6. 数据量增加后，近期列表查询不再依赖“读取全部训练明细后再截取”。
7. 全历史统计、训练频率和力量趋势仍使用完整真实数据，不能错误地只基于已加载列表计算。

## 非目标

- 不增加训练记录详情页或记录点击入口。
- 不增加日期、计划、类型或容量筛选。
- 不支持跳到指定页、指定年份或指定训练。
- 不自动在滚动到底时请求；加载必须由用户明确点击触发。
- 不修改头部动画、顶部统计结构、训练频率布局或力量趋势结构。
- 不修改当前日期、名称、容量、组数和时长的展示口径。
- 不为动画引入新的第三方动画库。

## 用户流程

### 首次进入

1. 仪表盘返回最近 6 条已完成训练。
2. 如果不存在第 7 条记录，不显示“加载更早记录”按钮。
3. 如果存在第 7 条记录，在列表末端显示“加载更早记录”。
4. 标题“近期训练”和“已完成记录”位于滚动区域之外，滚动时保持不动。

### 加载更多

1. 用户滚动到近期训练末端。
2. 用户点击“加载更早记录”。
3. 按钮立即进入按压反馈并切换为“正在追溯更早记录…”。
4. 当前已显示记录全部保留，不能闪白、清空或重新排序。
5. 请求成功后，把最多 20 条更早记录追加到现有列表末端。
6. 保持旧记录与新记录交界处的视觉位置稳定，不跳到新列表最底部。
7. 短暂显示“已载入 N 条更早记录”。
8. 如果仍有更多记录，列表末端重新出现“加载更早记录”。
9. 如果没有更多记录，显示“已经追溯到最早一次训练”。

### 加载失败

1. 已加载记录保持可读。
2. 加载区域切换为“加载失败，点击重试”。
3. 用户点击重试时继续使用同一个游标。
4. 失败请求不能推进游标、增加记录或改变循环色索引。

## 数据契约

### 初始仪表盘

`GET /api/dashboard` 中的近期训练部分调整为：

```ts
type WorkoutHistoryPageInfo = {
  hasMore: boolean;
  nextCursor: string | null;
};

type DashboardData = {
  // 其他字段保持不变
  recentWorkouts: WorkoutSummary[]; // 0–6 条
  recentWorkoutsPageInfo: WorkoutHistoryPageInfo;
};
```

规则：

- `recentWorkouts` 只包含已完成训练。
- 数组按 `started_at DESC, id DESC` 排序。
- 服务端内部读取 7 条，用第 7 条判断 `hasMore`，只返回前 6 条。
- `nextCursor` 指向已返回的第 6 条；不足 6 条或没有更多记录时为 `null`。
- `lastSession` 与 `recentWorkouts[0]` 使用相同的最新已完成训练口径。

### 历史分页接口

新增：

```text
GET /api/workouts/history?limit=20&cursor=<opaque-cursor>
```

成功响应：

```ts
type WorkoutHistoryPageResponse = {
  workouts: WorkoutSummary[];
  pageInfo: {
    hasMore: boolean;
    nextCursor: string | null;
  };
};
```

接口规则：

- 只允许当前登录用户读取自己的记录。
- 只返回 `completed_at IS NOT NULL` 的训练。
- `limit` 默认 20，最小 1，最大 20；当前界面固定请求 20。
- 查询读取 `limit + 1` 条，用额外一条判断 `hasMore`。
- 返回顺序固定为 `started_at DESC, id DESC`。
- `nextCursor` 基于本次实际返回的最后一条记录生成。
- 没有更多记录时返回空数组或最后一批不足 20 条，且 `hasMore = false`、`nextCursor = null`。
- 未登录返回 `401`。
- 游标缺失时允许返回最新一页；游标格式无效或字段越界时返回 `400`，不能默默回退到第一页。

### 游标

游标是后端生成的不透明 Base64URL 字符串，前端不得解析、拼接或修改。

游标内部至少包含：

```ts
{
  v: 1;
  startedAt: number;
  id: string;
}
```

下一页查询语义：

```sql
started_at < cursor.startedAt
OR (started_at = cursor.startedAt AND id < cursor.id)
```

使用 `id` 作为第二排序键，保证多条训练开始时间相同时不会重复或遗漏。分页期间新增一条更晚的训练，不应影响当前游标之后的旧记录读取。

## 数据分层

分页响应遵循：

```text
raw response
  → normalizeWorkoutHistoryPage()
  → RecentWorkouts view model
```

标准化层负责：

- 验证 `workouts` 是否为数组。
- 验证 `pageInfo.hasMore` 和 `pageInfo.nextCursor` 的组合是否合法。
- 把缺失或异常响应转为明确错误，不让页面层自行猜测。
- 保留 `volume_kg = 0`，不能把零值当空值。

展示层只消费标准化后的：

- `records`
- `hasMore`
- `nextCursor`
- `loadState`
- `statusMessage`

页面不直接解析游标，也不根据数组长度自行推断下一页游标。

## 服务端性能边界

### 近期列表

- 近期列表必须在数据库查询阶段限制为 6 或 20 条。
- 禁止继续使用“查询全部训练与训练组 → JavaScript 过滤完成记录 → `slice()`”生成近期列表。
- 单页训练容量和组数仍由真实 `workout_sets` 聚合产生。
- 为按训练记录聚合训练组补充或确认 `workout_sets(workout_session_id)` 索引。
- 复用现有训练会话用户与开始时间索引；只有查询计划证明不足时才新增非重复索引。

### 全历史统计

以下结果仍必须基于全部真实历史：

- 累计训练。
- 活跃周数。
- 连续完成。
- 训练频率。

这些结果改用计数、日期或按日聚合查询，不为统计读取每条训练的完整展示字段和全部训练组明细。

力量趋势继续保持当前“一年内同一动作真实训练组”的查询范围，不因近期训练分页改变。

## 前端状态模型

模块状态：

```ts
type HistoryLoadState =
  | "idle"
  | "loading"
  | "success"
  | "error"
  | "exhausted";
```

### idle

- 展示现有记录。
- `hasMore = true` 时显示“加载更早记录”。

### loading

- 保留所有记录。
- 加载按钮不可重复点击。
- 在原按钮占位内展示“正在追溯更早记录…”和轨迹续接动画。
- 不显示覆盖整个模块的 loading。

### success

- 追加并去重本批记录。
- 短暂显示“已载入 N 条更早记录”。
- 成功提示只负责反馈，不阻止滚动或下一步操作。

### error

- 保留记录和当前游标。
- 显示“加载失败，点击重试”。
- 错误状态使用明确文字，不能只依赖颜色。

### exhausted

- 不再发起分页请求。
- 列表末端显示“已经追溯到最早一次训练”。
- 时间线在该状态形成明确终点，不继续绘制空连接线。

### 状态重置

以下情况重置为最新 6 条及新游标：

- 登录用户变化。
- 退出登录。
- 仪表盘完成一次正式刷新并返回新的近期训练快照。
- 新训练完成后重新同步仪表盘。

不缓存跨账号或跨仪表盘快照的分页结果。

## 并发与去重

- 模块只保留一个 `loadMoreHistory()` 请求入口。
- `loading` 状态下按钮禁用，禁止并发发起同一游标请求。
- 不对明确点击操作做防抖或节流。
- 请求结果按 `id` 去重，后返回的重复记录不能覆盖顺序。
- 成功后才替换 `nextCursor`。
- 请求失败继续保留旧游标。
- 用户或仪表盘快照变化时，使在途旧请求失效；旧响应不得写回新账号或新快照。
- 当前不增加分页缓存；用户重新进入新的仪表盘快照时从最近 6 条重新开始。

## 滚动容器

结构分为：

1. 标题区：固定在滚动区域之外。
2. `.timeline-viewport`：只包含训练记录和列表末端状态。

滚动规则：

- 默认加载的 6 条都在容器内。
- 容器使用 `max-height: 440px`，少于 6 条时按实际内容高度收缩。
- 追加记录后容器高度不再增长，改为内部纵向滚动。
- `overflow-y: auto`，禁止横向滚动。
- 使用系统原生触摸惯性和滚动条，不制作独立的装饰滚动条。
- 移动端保持 `touch-action: pan-y`。
- 到达内部滚动边界后允许继续滚动外层页面，不能形成滚动陷阱。
- 标题、训练频率和力量趋势不进入内部滚动区域。
- 长名称只增加对应记录高度；因此部分短屏设备可能需要在容器内滚动才能看完第 6 条，这是允许的。

加载按钮位于列表末端，而不是固定覆盖在容器底部。用户必须到达当前记录末端后再主动加载更早记录。

## 颜色连续性

- 初始 6 条按全局索引 `0–5` 使用绿、橙、蓝循环。
- 新批次第一条使用索引 `records.length`，不能从绿色强制重新开始。
- 失败和重试不改变已有索引。
- 去重后按最终数组索引重新计算颜色，保证视觉节奏连续。
- 加载状态中的能量点可以依次经过绿、橙、蓝，但不能改变记录本身的颜色。

## “轨迹续接”动画

### 动画目标

动画只用于表达：

- 点击已经被接收。
- 系统正在读取更早记录。
- 新记录已连接到现有时间线。
- 已经到达训练历史终点。

不为普通滚动、现有记录或页面首次进入增加额外编排。

### 1. 按压反馈

- 时长：`120ms`。
- 加载按钮缩放至约 `0.97`，同时强调色增强。
- 使用现有 `--ease-out-quart`。
- 不能产生按钮宽高变化。

### 2. 加载轨迹

- 按钮在原有尺寸内切换为轨迹加载器，避免布局跳动。
- 文案：“正在追溯更早记录…”。
- 时间线末端出现一段短连接轨和移动能量点。
- 能量点在短轨内循环移动，颜色按绿、橙、蓝依次变化。
- 单次循环约 `720ms`；动画只在请求进行中存在。
- 加载器是局部骨架状态，不使用旋转菊花，不遮挡已有记录。
- 不人为延迟快速响应；接口很快时允许加载轨迹只出现一帧，按压和完成动画仍提供反馈。

### 3. 新记录接入

请求成功后：

- 先将时间线连接段以 `scaleY` 从旧末端向下展开，时长 `220ms`。
- 新记录从 `translateY(10px)`、`opacity: 0`、`blur(3px)` 进入正常状态。
- 单条进入时长 `240ms`，使用 `--ease-out-expo`。
- 仅本批前 8 条使用错峰，间隔 `24ms`，总错峰不超过 `168ms`。
- 第 9–20 条立即处于正常显示状态，避免滚动过程中持续表演。
- 不动画 `height`、`top`、`left`、margin 或其他主要布局属性。
- 动画开始前内容必须已经可访问；即使动画未运行，记录也不能保持隐藏。

### 4. 滚动锚点

- 请求前记录当前内部 `scrollTop` 和旧列表末端锚点。
- 追加记录后阻止浏览器把用户直接锚定到新列表最底部。
- 旧末条与新首条的交界位置保持稳定。
- 正常动画模式下，可以在 `220ms` 内向下推进最多 `32px`，仅用于露出新首条的时间线圆点。
- 减少动态模式下不做平滑推进，保持原位置。

### 5. 完成反馈

- 文案：“已载入 N 条更早记录”。
- 状态切换动画 `180ms`，文案保留约 `900ms`。
- 如果还有更多记录，反馈结束后恢复“加载更早记录”。
- 如果没有更多记录，直接进入终点状态。

### 6. 终点

- 时间线最后圆点进行一次 `160ms` 的亮度脉冲后稳定。
- 文案：“已经追溯到最早一次训练”。
- 不使用粒子、彩带、弹跳或持续发光。

## 减少动态效果

在 `prefers-reduced-motion: reduce` 下，仅对本模块降级：

- 关闭能量点移动、颜色循环、模糊、位移、错峰和终点脉冲。
- 加载器保留静态连接轨和“正在追溯更早记录…”文字。
- 新记录立即出现。
- 不执行平滑滚动推进。
- 成功、失败和终点文案保持完整。
- 不用全局规则关闭头部或其他模块既有动画。

## 可访问性

- 加载按钮最小触控高度 `44px`。
- 加载中使用 `disabled` 和 `aria-busy="true"`。
- 模块滚动区域具有明确可访问名称，例如“近期训练记录”。
- 成功、失败和终点信息通过独立 `aria-live="polite"` 区域播报。
- 失败重试仍是明确按钮，不把文字或时间线圆点伪装成点击目标。
- 颜色不作为加载、失败或终点状态的唯一表达。
- 键盘用户可以聚焦加载按钮，并使用方向键、Page Up / Page Down 滚动列表。
- 记录顺序与 DOM 顺序一致，不通过视觉变换改变阅读顺序。

## 空状态与边界

### 0 条

- 保留原真实空状态。
- 不显示滚动容器、加载按钮、加载轨迹或终点文案。

### 1–5 条

- 模块按内容高度收缩。
- 不显示加载按钮。
- 最后一条记录正常停止时间线。

### 恰好 6 条且没有更多

- 展示 6 条。
- 不显示加载按钮。
- 不额外占用一行显示终点文案。

### 恰好 6 条且有更多

- 列表末端显示“加载更早记录”。
- 点击后请求最多 20 条。

### 最后一批不足 20 条

- 正常追加实际返回数量。
- 成功提示使用实际数量。
- 随后进入终点状态。

### 返回空数组但 `hasMore = true`

- 视为响应契约错误。
- 不推进游标。
- 进入可重试错误状态，并记录开发日志。

### 重复 ID

- 前端去重。
- 如果去重后本批没有新增记录但服务端仍返回 `hasMore = true`，进入错误状态，避免无限重复请求。

## 验收标准

### 数据与接口

1. 初始仪表盘最多返回 6 条已完成训练。
2. 每次加载更多最多返回 20 条更早记录。
3. 多条相同 `started_at` 的训练跨页不重复、不遗漏。
4. 新增更晚训练不影响已经持有的旧记录游标继续分页。
5. 无效游标返回 `400`。
6. 未登录返回 `401`。
7. `0 kg`、组数、时长和长名称口径与现有模块一致。
8. 全历史统计和训练频率不因近期列表只加载 6 条而减少。
9. 近期列表查询在数据库阶段限制条数，不读取全部展示明细后再截取。

### 布局与滚动

10. 记录不足 6 条时模块自然收缩。
11. 加载超过 6 条后，近期训练高度不超过 `440px`。
12. 新增 20 条后，力量趋势位置不继续向下移动。
13. 模块只能纵向滚动，不产生横向溢出。
14. 内部滚动到边界后可以继续滚动外层页面。
15. 长名称、较大容量和 `0 kg` 仍保持三列对齐。
16. 记录颜色跨批次连续循环。

### 状态与动画

17. 加载中保留全部已有记录，按钮不能重复点击。
18. 加载轨迹只在请求期间出现。

## 风险与控制

### 移动端嵌套滚动

- 风险：内部列表可能截获外层页面滚动。
- 控制：只使用纵向原生滚动，到达边界后允许滚动链传递，不使用持续阻止默认事件的手势代码。

### 追加后跳到底部

- 风险：浏览器滚动锚定可能跟随列表末端按钮移动，导致用户跳过新记录。
- 控制：记录并恢复旧锚点，加载按钮不作为追加后的浏览器锚点。

### 动画影响性能

- 风险：一次插入 20 条并同时执行模糊和位移动画可能掉帧。
- 控制：只动画前 8 条，限制模糊范围，动画结束后不保留 `will-change`。

### 游标重复或遗漏

- 风险：仅用时间戳分页时，相同开始时间会重复或丢失。
- 控制：游标同时使用 `started_at` 和 `id`，服务端与前端固定同一排序规则。

### 统计被分页截断

- 风险：把 `recentWorkouts` 误当全历史数据源，会导致累计训练和频率变小。
- 控制：全历史统计使用独立聚合查询，禁止根据前端分页数组计算。

### 旧请求污染新账号

- 风险：退出登录或切换账号时，旧分页响应写回新状态。
- 控制：账号或仪表盘快照变化时废弃在途请求，响应落地前核对当前请求上下文。
