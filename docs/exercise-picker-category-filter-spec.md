# 动作选择器分类筛选规格

## 背景

计划页的动作选择器目前把全部动作平铺在同一个列表中。搜索可以按动作名称、器械和肌群定位，但用户在没有明确动作名称、希望浏览可选动作时，需要逐行扫描整个列表。

当前固定动作库共有 18 个动作，已经可以形成清晰的三类浏览入口：

- 力量：13 个。
- 有氧：2 个。
- 核心：3 个。

本次在保留现有搜索和动作行信息的基础上，增加轻量分类筛选，降低移动端浏览动作的成本。

## 已确认方向

动作选择器采用“搜索框 + 顶部分类标签 + 动作列表”的结构。

分类顺序固定为：

```text
全部 18    力量 13    有氧 2    核心 3
```

- 默认选中“全部”。
- 分类采用扁平文字标签和底部选中线，不使用胶囊按钮、卡片或额外描边框组。
- 动作行继续显示“动作名称 + 器械 · 肌群”，不重复增加分类徽标。
- 第一版不增加胸、背、腿等二级肌群筛选。

## 目标

1. 用户无需输入关键词，也能快速缩小动作浏览范围。
2. 保留搜索对动作名称、器械和肌群的现有支持。
3. 移动端增加分类后，弹层仍保持足够的可滚动动作区域。
4. 分类只影响动作选择器的展示结果，不改变计划、训练和历史数据口径。
5. 桌面端与移动端使用同一套分类和搜索规则。

## 不在本次范围

- 不重新设计动作选择弹层、动作行、动作编辑器或添加动作按钮。
- 不增加肌群、器械、训练部位等多级筛选。
- 不增加“最近使用”“收藏动作”或排序设置。
- 不修改训练计划保存、今日训练生成、训练快照或历史记录逻辑。
- 不修改数据库表、动作接口字段或已有计划数据。
- 本次不新增或启用自定义动作，但保留现有兼容代码、接口和数据结构，作为后续开发能力。
- 不修改计划页顶部共享元素动画、星期切换、训练日状态开关和保存栏。

## 信息结构

### 移动端

动作选择底部弹层的纵向结构为：

```text
选择动作                         关闭
搜索动作、器械或肌群
全部 18    力量 13    有氧 2    核心 3
────────────────────────────────────
动作列表（独立滚动）
```

- 标题、搜索框和分类标签保持在动作列表上方。
- 动作列表继续作为唯一纵向滚动区域，不能带动页面背景滚动。
- 弹层整体高度继续受现有移动端视口上限约束，不因分类栏无限增高。
- 分类栏占用一个紧凑的 `44px` 交互行，动作列表使用剩余空间。

### 桌面端

- 分类栏位于搜索框下方、动作列表上方。
- 弹出菜单保持与触发器对齐，并继续根据上下可用空间选择展开方向。
- 分类栏加入后，菜单总高度仍受视口空间限制；动作列表高度缩短并独立滚动。

## 分类视觉

- 分类标签等宽分布在一行内。
- 未选中标签使用当前低强调文字颜色。
- 选中标签使用亮绿色文字，并显示短底线。
- 数量使用更低一级的等宽数字样式，不与分类名称争夺注意力。
- 不只依赖颜色表达选中状态；底线和可访问状态同时存在。
- 标签整体点击区域高度不小于 `44px`。
- 分类切换只使用短促的颜色和底线过渡，不让列表横向滑动。
- `prefers-reduced-motion: reduce` 下取消非必要过渡。

## 分类规则

分类是动作选择器中的单一主要浏览类别。虽然核心动作也可能属于力量训练，但第一版按动作的主要训练目的只归入一个分类，避免同一动作重复出现。

### 固定动作

#### 有氧

- 跑步机热身。
- 爬坡。

#### 核心

- 平板支撑。
- 死虫。
- 卷腹。

#### 力量

- 除上述 5 个动作外的其他 13 个固定动作。

固定动作使用稳定 `exerciseId` 显式归类，不能只根据中文名称判断。

### 后续自定义动作

自定义动作是明确保留的后续开发能力，但当前计划页没有创建入口，动作选择器也只消费固定 `exerciseLibrary`，因此不参与本次分类数量和过滤。

- 不删除或收缩现有自定义动作兼容分支、接口与数据库结构。
- 本次不为尚未开放的自定义动作推导分类，也不提前新增分类字段。
- 后续正式开发自定义动作时，应在创建或编辑流程中明确选择分类，并让分类数量自然包含当前用户的自定义动作。
- 后续能力的字段、默认分类、历史兼容和迁移方案需要单独写规格，不由本次实现提前决定。

## 数量规则

- “全部”数量为当前固定动作库 `options` 的总数。
- 各分类数量按完整固定动作库计算。
- 搜索过程中数量保持为完整分类数量，不随搜索结果跳动。
- 分类数量为 `0` 时仍保留该标签，便于用户理解完整分类结构。
- 数量发生变化时不做强调动画。

## 交互规则

### 打开选择器

1. 每次打开时，搜索词为空。
2. 每次打开时，分类重置为“全部”。
3. 搜索框继续自动获得焦点。
4. 当前已选动作继续显示勾选状态。

### 切换分类

1. 点击分类后立即更新动作列表，不关闭选择器。
2. 已有搜索词时，分类筛选作用于当前搜索结果。
3. 切换分类后，键盘活动项重置到过滤结果的第一项。
4. 列表滚动位置回到顶部，避免用户落在新分类的中间位置。
5. 分类中没有动作时显示明确空状态，不回退到“全部”。

### 搜索

1. 搜索词从空变为非空时，分类自动切回“全部”。
2. 搜索继续匹配动作名称、器械和肌群。
3. 搜索结果按原始动作顺序展示，不额外按分类重排。
4. 用户输入搜索词后，仍可再次点击“力量 / 有氧 / 核心”缩小搜索结果。
5. 清空搜索词后保留用户当前选择的分类。
6. 关闭选择器时清空搜索词并重置分类。

### 选择动作

- 点击动作后继续沿用现有 `onSelect(exerciseId)` 行为并关闭选择器。
- 分类不能改变动作值、动作顺序或计划编辑器中已填写的组数、次数、时长、重量记录方式和提示。
- 分类同时适用于“替换已有动作”和“选择要添加的动作”两个入口。

## 空状态

### 分类为空

```text
该分类暂无动作
可以查看其他分类或使用搜索。
```

### 搜索无结果

继续使用现有文案：

```text
没有匹配动作
换个关键词再试试。
```

如果同时存在搜索词和分类筛选，搜索无结果状态优先，并允许用户直接切换分类或清空搜索。

## 键盘与可访问性

- 分类标签使用真实 `button`。
- 当前分类通过 `aria-pressed="true"` 或等价的单选语义表达。
- 分类栏提供可访问名称“动作分类”。
- `Tab` 可以依次访问搜索框、分类标签和动作选项。
- 分类切换后同步更新 `aria-activedescendant`，不能指向已经被过滤掉的动作。
- 搜索结果或分类为空时，不保留无效的活动项。
- `Escape`、方向键、`Home`、`End`、`Enter` 和焦点返回行为继续符合现有选择器逻辑。
- 移动端触控区域不小于 `44px`，清楚区分分类点击和动作列表纵向滑动。

## 数据与实现边界

第一版分类属于动作选择器的展示派生状态：

```ts
type ExerciseCategory = "strength" | "cardio" | "core";
type ExerciseCategoryFilter = "all" | ExerciseCategory;
```

- 固定动作按 `exerciseId` 映射分类。
- 分类数量和过滤结果都从当前 `options` 派生。
- 不把分类写入 `PlanExercise`、训练计划接口、训练快照或训练历史。
- 不新增 D1 迁移，不改变 `/api/exercises` 响应结构。
- 不清理现有自定义动作预留能力；本次选择器仍只使用固定动作库。
- 分类与搜索组合应集中在可测试的纯函数或派生逻辑中，避免 UI 分支重复实现规则。

## 状态模型

选择器增加以下本地状态：

```ts
type ExerciseCategoryFilter = "all" | "strength" | "cardio" | "core";

query: string;
category: ExerciseCategoryFilter;
activeIndex: number;
```

派生顺序固定为：

```text
options
  → 搜索匹配
  → 分类筛选
  → filtered options
```

搜索词首次输入时先把 `category` 设为 `all`，再按新的搜索词计算结果。

## 风险与处理

### 核心与力量概念重叠

按主要训练目的建立互斥分类。核心动作只出现在“核心”，不在“力量”重复展示。

### 分类后键盘索引失效

搜索或分类发生变化时重置活动项，并保证 `aria-activedescendant` 只引用当前过滤结果。

### 移动端列表空间减少

分类栏固定为单行紧凑结构，弹层总高度不增加，列表使用剩余空间滚动；需要在 `390 × 844` 及更矮视口检查可用性。

## 验收标准

1. 桌面端和移动端动作选择器都在搜索框下方显示“全部 / 力量 / 有氧 / 核心”。
2. 当前固定动作数据下显示 `全部 18 / 力量 13 / 有氧 2 / 核心 3`。
3. 跑步机热身、爬坡只出现在“有氧”。
4. 平板支撑、死虫、卷腹只出现在“核心”。
5. 其他 13 个固定动作只出现在“力量”。
6. 搜索词从空变为非空时自动切回“全部”，搜索仍覆盖名称、器械和肌群。
7. 搜索后可以再次选择分类缩小结果，清空搜索后保留当前分类。
8. 每次重新打开选择器时，搜索为空且分类为“全部”。
9. 切换搜索或分类后，列表从顶部显示，键盘活动项和读屏状态准确。
10. 选择动作后，现有替换、添加和关闭行为不变。
11. 分类不会修改计划、训练快照、历史记录或动作接口数据。
12. 现有自定义动作兼容代码、接口和数据结构不会因本次分类功能被删除。
13. 移动端弹层不超出视口，背景不跟随滚动，分类和动作触控区域不小于 `44px`。
14. 桌面端菜单仍能根据空间向上或向下展开，不被计划页滚动容器裁切。
15. `prefers-reduced-motion: reduce` 下分类切换没有非必要动效。
16. 分类纯函数、搜索与分类组合、空状态和重置行为有定向自动测试。
17. TypeScript、ESLint、定向测试、生产构建和 `git diff --check` 全部通过。
