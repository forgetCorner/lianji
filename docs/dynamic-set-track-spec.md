# 训练页动态组数进度设计规格

## 背景

训练动作的组数完全来自计划中的 `minSets` 和 `maxSets`，不能只适配 1 组、3 组或 2–3 组等示例。考虑到本产品的训练场景，单个动作统一限制为 1–6 组。

原有刻度点不容易被理解为进度，因此改为简约编号序列：每一组直接显示为 `01...06`，并用完成图标、当前扫描角标、状态文案和目标区括线共同表达进度。

## 目标

1. 用户能立即看懂已完成几组、当前进行第几组。
2. 清楚区分最低目标内的组数与可选加练组。
3. 同一组件覆盖所有 1–6 组配置，不硬编码具体组数组合。
4. 1–4 组保持舒展，5–6 组自动切换紧凑布局。
5. 不增加卡片容器、多余线条和花哨装饰。

## 数据与限制

- `minSets`：至少需要完成的组数。
- `maxSets`：允许完成的最大组数。
- `completedSets`：已经保存成功的组数。
- `currentSet`：未完成时为 `completedSets + 1`。
- 有效范围：`1 <= minSets <= maxSets <= 6`。

计划页输入超过 6 时不更新原值，并显示“每个动作最多 6 组”。保存接口对超过 6 的请求返回 400，防止绕过前端写入异常数据。

## 展示结构

### 顶部摘要

- 左侧：`组数进度`
- 右侧：`已完成 n / m 组`

### 编号序列

- 根据 `maxSets` 生成 `01...0N`。
- 1–4 组使用大号编号。
- 5–6 组使用紧凑编号，仍完整显示在移动端内容宽度内。
- 不为每个编号添加卡片、圆角底板或完整边框。

### 编号状态

- 已完成：亮绿色编号、小型完成图标和“完成”。
- 当前必做组：橙色编号、扫描角标和“第 N 组 · 进行中”。
- 当前加练组：橙色编号、扫描角标和“第 N 组 · 加练中”。
- 未开始：中性灰色和“待开始”。
- 5–6 组紧凑模式只保留当前组状态文案，避免拥挤。

### 目标分区

- 编号下方只使用一条括线标记最低目标区。
- 未达到时显示 `最低目标 N 组`，达到后显示 `最低目标已达`。
- `minSets < maxSets` 时，剩余编号不增加第二个括线，当前加练组直接显示“加练中”。

## 业务规则

1. `minSets === maxSets === 1`：单组模式。
2. `minSets === maxSets > 1`：固定组数模式。
3. `minSets < maxSets`：弹性组数模式。
4. 完成组数小于 `maxSets` 时，下一组为当前组。
5. 完成 `maxSets` 后不生成越界节点。
6. 超过最低目标后的组属于加练，但沿用现有可继续训练逻辑。

## 动效

- 当前编号使用轻微透明度呼吸，不缩放、不改变布局尺寸。
- 完成本组后，当前编号转为绿色，下一个编号变为橙色。
- 不让整条序列重新挂载或从第一组重播。
- `prefers-reduced-motion: reduce` 下取消呼吸动画。

## 响应式与可访问性

- 移动端 1–6 个编号必须完整显示，不产生横向滚动。
- 双位编号不能重叠、截断或越界。
- 整体提供包含目标、完成数量和当前组的 `aria-label`。
- 状态同时通过颜色、图形和文字表达。
- 进度序列只读，不添加虚假按钮语义。

## 不在本次范围

- 不修改数据库字段。
- 不改变训练达到最低组数或最大组数后的既有业务流程。
- 不重新设计重量、次数、速度、坡度和时间输入区。

## 验收标准

1. 支持计划数据中的所有 1–6 组配置。
2. 单组、固定组数和弹性组数文案与状态正确。
3. 最低目标区通过括线表达，加练状态通过橙色当前编号和“加练中”表达。
4. 完成、当前、未开始三类状态可被直接识别。
5. 5–6 组在移动端不拥挤、不横向滚动。
6. 计划页不能输入超过 6 组，并出现明确提示。
7. 保存接口拒绝超过 6 组的请求。
8. TypeScript、ESLint、生产构建、相关测试和 `git diff --check` 全部通过。
