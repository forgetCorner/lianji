# 当天动态计划训练单规格

## 背景与问题

当前系统在计划训练的所有动作完成后，会立即将训练会话标记为完成并从“进行中训练”中移除。这会导致用户在当天再次编辑周计划、添加动作后，无法在原训练上继续。

同时，当前保存周计划时会重新生成训练日和计划动作的 ID，这使系统无法稳定判断“原有动作”、“新增动作”和“已删除动作”。

本次改造将“完成当前计划”与“冻结历史记录”分开：当天的计划训练在零点前保持可同步，进入下一个自然日后才成为不受后续计划修改影响的历史快照。

## 目标

1. 同一用户在同一个上海时区自然日内，同一个当日计划只产生一条计划训练单。
2. 当天完成当前计划后，不再允许重新开始同一计划训练。
3. 当天在计划中新增动作后，将新动作追加到原训练单，页面恢复“继续训练”。
4. 删除尚未完成的动作后，不再将该动作计入当天待完成任务。
5. 已经完成的训练事实不因计划后续删除或修改而丢失。
6. 进入次日零点后，前一天的训练单冻结，不再与新计划同步。

## 核心概念

### 业务日期

- 统一使用 `Asia/Shanghai` 时区计算业务日期。
- 训练单保存 `YYYY-MM-DD` 格式的业务日期，不仅依赖训练开始时间推断归属日期。
- 服务端是日期边界的唯一权威判断方，不信任客户端传入的日期。

### 当天训练单

- 记录当天计划实际执行过程。
- 零点前可根据当前周计划的动作成员变化进行同步。
- 完成状态是“当前已无待完成计划动作”，不代表记录已经永久冻结。

### 冻结训练快照

- 业务日期早于当前上海日期时，训练单视为已冻结。
- 冻结后保留当日实际完成的动作、组数、重量、次数、时长和当时的动作快照。
- 后续修改周计划不影响已冻结训练。

## 当天状态机

| 状态 | 判断 | 今日页行为 |
| --- | --- | --- |
| 未开始 | 当天没有计划训练单 | 显示“开始训练” |
| 进行中 | 当天训练单存在至少一个未删除、未完成动作 | 显示“继续 + 当前动作名” |
| 已完成 | 当天训练单不存在未删除、未完成动作 | 显示不可点击的“今日训练已完成”，不显示重新开始 |
| 已冻结 | 训练日期早于当前业务日期 | 只进入历史统计，不参与今日操作 |

状态转换规则：

1. `未开始 -> 进行中`：用户首次点击“开始训练”，根据当前计划创建快照。
2. `进行中 -> 已完成`：最后一个待完成动作完成，或所有剩余待完成动作都被从计划删除。
3. `已完成 -> 进行中`：当天计划新增至少一个未出现在训练单中的动作。
4. `任意当天状态 -> 已冻结`：进入下一个上海自然日。

## 计划动作同步规则

### 稳定身份

- 训练日 ID 和计划动作 ID 必须在普通编辑、排序和保存后保持不变。
- 真正新增的计划动作获得新 ID。
- 删除后再新建的动作，即使来自同一动作库项，也视为新的计划动作。
- 服务端必须验证客户端传入的旧 ID 归属当前用户，新 ID 不得与其他用户数据冲突。

### 新增动作

- 如果当天尚未创建训练单，只更新计划，仍等待用户点击“开始训练”。
- 如果当天训练单已存在且未冻结，为新动作追加一条未完成训练动作快照。
- 如果原训练单已完成，新增动作使其恢复为进行中。
- 新动作按最新计划顺序显示，“继续训练”定位到第一个未完成动作。

### 删除尚未完成动作

- 不物理删除当天训练快照，而是将其标记为已从当前计划移除。
- 被移除的未完成动作不再阻止当天训练完成。
- 若移除后不再存在待完成动作，当天训练立即进入已完成状态。
- 同一计划动作在当天再次恢复时，取消移除标记；如果之前未完成，它再次成为待训练动作。

### 删除已完成动作

- 保留该动作和已记录训练组，因为它代表当天真实发生的训练。
- 将其标记为已从当前计划移除，但历史容量、组数和力量趋势继续统计该训练数据。
- 删除已完成动作不会要求用户重新训练。

### 修改动作与排序

- 只修改名称、器械、部位、目标或顺序时，不将其识别为新动作。
- 已完成动作继续保留完成时快照，修改目标不会重新打开该动作。
- 尚未产生任何训练组的未完成动作，可以同步最新名称、器械、目标和顺序。
- 已产生部分训练组但尚未完成的动作，保留开始执行时的记录方式和重量模式，避免新设置与旧训练组不兼容。

## 计划与训练快照的数据边界

### 计划数据

- 表示用户当前和未来要执行的周计划。
- 训练日和动作 ID 是用于跨版本识别的稳定业务身份。
- 计划版本仍用于多设备并发修改检测。

### 训练动作快照

- 保存开始训练时的动作配置，以及当天后续追加的新动作。
- 通过稳定的计划动作 ID 与当前计划对齐。
- 需要保存“是否已从当前计划移除”的状态或时间，不能用“已跳过”代替，因为计划删除和用户主动跳过的语义不同。

### 建议字段语义

具体迁移名称可在实施计划中根据现有 schema 确定，但必须表达以下语义：

- 训练会话：业务日期、当前完成时间、冻结时间、最后同步的计划版本。
- 训练动作：稳定计划动作 ID、从当前计划移除的时间。
- 当天计划训练单必须有用户与业务日期范围的唯一性保护，防止连点或多设备重复创建。

## 同步时机

为了不依赖后台定时任务，采用服务端惰性冻结和幂等同步。

1. 读取今日页、查询当天训练或进入训练页时，先将过期未冻结训练标记为冻结。
2. 保存周计划成功后，如果当天已存在未冻结训练，立即执行动作差异同步。
3. 点击“开始训练”时再次执行查重，避免多设备同时创建两条训练。
4. 保存训练组、完成动作、跳过动作和完成训练时，服务端重新校验业务日期和冻结状态。
5. 所有同步操作必须幂等，同一计划版本重复调用不能重复追加动作。

## 跨零点行为

- 零点后对前一天训练的任何写操作必须被服务端拒绝。
- 如果用户在训练页停留到跨日，下一次保存时返回明确的跨日状态，客户端退回新的今日页并重新同步。
- 跨日时仍未完成的训练以“未完成快照”冻结，不自动并入第二天。
- 当页面持续打开时，前端应在跨日后刷新今日状态；后端日期校验仍是最终保护。

## 今日页展示规则

### 动作状态

- 已完成：当天训练单中对应动作有完成时间。
- 当前动作：当天训练单中第一个未删除、未完成动作。
- 未开始：没有对应训练快照，或有快照但尚未到当前动作。
- 已从计划移除的未完成动作不再出现在今日计划列表。
- 今日页不使用位置、动作名称或动作库 ID 猜测完成状态，只通过稳定的计划动作 ID 映射。

### 底部操作

- 未开始：主按钮“开始训练”。
- 进行中：主按钮“继续 {currentExerciseName}”。
- 已完成：保留同等尺寸的完成状态提示“今日训练已完成”，不可点击，不再触发创建训练。
- 已完成后新增动作：完成提示自动切换为“继续 {newExerciseName}”。

## API 行为边界

- 创建训练接口在当天已有训练单时不创建第二条，而是返回已存在的当天训练状态或明确冲突。
- 查询“进行中训练”不足以支持今日页；客户端需要获得当天训练的未开始、进行中或已完成状态。
- 计划保存和当天训练同步要么在同一个服务端原子流程中完成，要么保证计划保存后的同步可重试且幂等。
- 已冻结训练的保存组、完成动作、跳过和结束接口统一拒绝写入。

## 并发与一致性

- 多设备同时点击开始时，唯一索引必须保证当天只有一条计划训练单。
- 计划保存仍使用版本号乐观锁，旧版本不能覆盖新版本。
- 动作追加使用训练单与计划动作 ID 的唯一性保护，重复同步不产生重复动作。
- 当计划修改与训练组保存几乎同时发生时，已成功写入的训练组不能被计划同步删除。

## 数据迁移与兼容

- 现有已完成训练默认视为已冻结历史，不追溯同步当前计划。
- 现有进行中训练根据开始时间计算业务日期；如果日期早于当天，迁移后立即冻结。
- 无法与当前计划通过稳定 ID 对齐的旧训练快照，保留原记录，但不利用位置或名称进行冒险回填。
- 新字段必须提供可安全回填的默认值，数据库初始化和旧数据升级均不能丢失训练组。

## 异常与空状态

- 当天计划被设为休息日且已存在训练单时，所有未完成动作按从计划移除处理；已完成数据保留。
- 当天计划重新开启后，按稳定动作 ID 恢复或追加动作。
- 如果同步失败，今日页不得伪造本地完成状态，而应保留服务端最后确认状态并提示重新同步。
- 若当天没有启用计划，本次不提供计划外自由训练入口。

## 不在本次范围

- 计划外自由训练、临时动作和多次训练。
- 一天内重复执行同一计划。
- 手动解锁或修改已冻结历史记录。
- 将未完成训练自动延续到第二天。
- 后台定时任务或补数管理界面。

## 验收场景

1. 当天无训练单时，可点击“开始训练”且只创建一条训练单。
2. 原计划 6 个动作全部完成后，页面显示“今日训练已完成”，不能重新开始。
3. 完成后当天新增第 7 个动作，页面立即显示“继续 + 新动作名”，原 6 个动作仍为已完成。
4. 原计划 6 个动作完成 5 个后删除唯一未完成动作，训练立即进入已完成状态。
5. 删除已完成动作后，其训练组、容量和力量趋势数据仍存在。
6. 已完成动作的目标组数被改大后，不会因此要求重新补练。
7. 未产生训练组的待完成动作修改名称、器械和目标后，继续训练显示最新内容。
8. 同一计划连续保存多次后，未删除训练日和动作的稳定 ID 保持不变。
9. 跨过上海时区零点后，前一天训练不再被计划新增或删除动作改变。
10. 多设备同时创建或同步时，不产生重复当天训练单或重复训练动作。
11. 现有历史训练和训练组在数据迁移后仍可读取、统计和展示。
12. ESLint、生产构建、自动化测试和 `git diff --check` 全部通过。
