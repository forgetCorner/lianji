# 今日页共享元素折叠动效实施计划

> 状态：已实施，待视觉确认
>
> 对应规格：[today-shared-element-transition-spec.md](./today-shared-element-transition-spec.md)
>
> 推荐执行方式：主代理直接实施并在真实移动端视口中逐帧验收

## 1. 实施目标

把今日页当前的“主体淡出 + 固定栏副本淡入”改成滚动驱动的共享元素过渡：

- 圆形训练状态图标从计划主体移动并缩小到固定栏。
- “全身 A / B / C”等计划名称从大标题移动并缩小到固定栏。
- 固定栏不再显示另一套波形图标和重复计划名称。
- “今天 ·”只作为补充语义在过渡后半段出现。
- 正向滚动、反向滚动、快速惯性滚动均保持连续。

## 2. 技术决策

### 2.1 采用自定义 FLIP 测量，不使用离散 `layoutId` 切换

Motion 的 `layoutId` 适合两个布局状态之间的一次性切换，但本需求需要动画进度与滚动位置逐帧绑定。实现采用自定义 FLIP：

1. 测量主体图标和标题的初始矩形。
2. 测量固定栏中图标槽位和标题槽位的目标矩形。
3. 根据滚动进度计算当前矩形。
4. 只用 `translate3d` 与 `scale` 把共享视觉层移动到当前矩形。

不新增动画依赖；项目已有的 Motion 保持不变。

### 2.2 使用单一可见视觉层

- 原始图标与标题继续保留在文档流中，负责布局和语义。
- 过渡开始后，原始视觉透明，但不移除、不改变尺寸。
- 新增一个 `aria-hidden="true"`、`pointer-events: none` 的共享视觉层，从原始元素的像素位置无缝接管。
- 共享视觉层从起点一直显示到固定状态，不在结尾交给另一套可见副本。
- 固定栏只提供目标槽位和背景，不再渲染独立的训练图标及计划名称。

这样可以避免当前交叉淡入淡出产生的视觉断点，同时保留唯一的语义标题。

### 2.3 滚动直接驱动，不增加追赶动画

- 继续使用 `.app-content` 作为移动端和桌面端的滚动容器。
- 每次滚动只调度一个 `requestAnimationFrame`。
- 动画进度直接来自最新 `scrollTop`，不使用持续 `lerp` 追赶，避免手指停止后元素仍继续移动。
- 通过分段的平滑映射控制视觉节奏，而不是让元素落后于滚动位置。

## 3. 组件与文件调整

### 3.1 新增 `components/today-shared-transition.tsx`

组件职责：

- 接收计划名称、计划字母、恢复日状态和滚动容器引用。
- 渲染共享训练状态图标、共享标题以及补充文字“今天 ·”。
- 接收或管理以下 DOM 引用：
  - 主体图标起点。
  - 主体标题起点。
  - 固定栏图标目标槽位。
  - 固定栏标题目标槽位。
- 保存测量结果，不在 React state 中逐帧写入滚动值。
- 通过元素 `style.transform` 或 CSS 自定义属性批量更新共享视觉层。
- 在组件卸载时移除监听器并取消未完成的动画帧。

建议组件接口：

```ts
type TodaySharedTransitionProps = {
  planName: string;
  planLetter: string | null;
  recovery: boolean;
  scroller: HTMLElement | null;
  sourceIconRef: RefObject<HTMLElement | null>;
  sourceTitleRef: RefObject<HTMLHeadingElement | null>;
  targetIconRef: RefObject<HTMLElement | null>;
  targetTitleRef: RefObject<HTMLElement | null>;
};
```

最终接口可根据现有 `TodayView` 拆分方式收敛，但业务数据不得进入组件内部请求。

## 4. FLIP 计算流程

### 4.1 初始测量

在以下时机测量：

- 今日页首次完成数据渲染。
- 计划名称、计划字母或恢复状态变化。
- 视口尺寸变化。
- 移动设备方向变化。
- 字体加载完成。
- 从其他底部模块切换回今日页。

使用 `ResizeObserver` 监听今日页内容区和固定目标槽位。测量只保存矩形数据，不触发视觉动画。

### 4.2 当前矩形计算

每帧输入：

- 当前 `scrollTop`。
- 归一化折叠进度 `p`。
- 起点矩形 `sourceRect`。
- 目标矩形 `targetRect`。

计算规则：

1. `p <= 0.12`：共享层与原始元素完全重合。
2. `0.12 < p < 0.78`：
   - 起点纵坐标先扣除滚动容器的自然位移。
   - 再在自然位置与固定目标位置之间插值。
   - 宽高同比例插值为 `scale`。
3. `p >= 0.78`：共享层稳定落入目标槽位。
4. `p >= 0.68`：“今天 ·”开始淡入，在约 `0.9` 达到完整状态。

图标和标题使用相同主进度，但可以使用不同的目标间距，不能各自使用不同延迟造成脱节。

### 4.3 写入顺序

单个动画帧内：

1. 读取最新滚动位置。
2. 使用缓存矩形完成纯数学计算。
3. 一次性写入图标 transform、标题 transform、前缀 opacity 和 `--header-collapse`。

滚动帧内不调用 `getBoundingClientRect()`；布局读取只发生在重测阶段。

## 5. 响应式与动态降级

### 移动端

- 使用 `.app-content` 的真实可滚动区域作为位置参照。
- 固定目标距离内容区左侧 `24px`。
- 共享图标约 `22px`，固定标题约 `15px`。
- 检查 iOS 风格惯性滚动、快速反向拖动和底部按钮遮挡。

### 桌面端

- 目标位置基于 `.app-content`，不把 `88px` 侧边栏重复计入。
- 共享图标约 `24px`。
- 检查宽屏、窄桌面和侧边栏边界。

### `prefers-reduced-motion`

- 不挂载或不更新共享位移层。
- 折叠阈值前显示主体图标与标题。
- 折叠阈值后直接显示固定状态。
- 不出现主体与固定状态同时可见的重叠帧。

## 6. 实施顺序

### 阶段一：结构与测量

1. 为源图标、源标题和两个目标槽位增加 refs。
2. 建立共享视觉层，先验证滚动为 `0` 时与主体像素级重合。
3. 建立重测机制，验证移动端和桌面端的目标坐标。

### 阶段二：滚动驱动

1. 整理现有折叠进度计算，移除会造成追赶感的持续平滑循环。
2. 接入图标的 FLIP 位移和缩放。
3. 接入标题的 FLIP 位移和缩放。
4. 加入“今天 ·”后半段淡入和固定栏背景接管。

### 阶段三：状态与边界

1. 验证全身 A / B / C。
2. 验证较长自定义计划名称。
3. 验证“没有固定训练”。
4. 验证正向、反向、快速惯性滚动和菜单切换。
5. 完成减少动态效果降级。

### 阶段四：清理与回归

1. 删除旧固定栏重复内容和不再使用的淡入样式。
2. 确认没有残留的重复语义节点。
3. 运行代码检查、生产构建和现有测试。
4. 通过真实浏览器录制移动端完整往返折叠视频供确认。

## 7. 验证计划

### 自动化检查

```bash
npm run lint

git diff --check
```

### 真实浏览器验收

至少覆盖以下环境：

1. `390×844`：正常缓慢下滑与反向恢复。
2. `375×812`：快速拖动和惯性滚动。
3. `1440×900`：桌面侧边栏与内容区坐标。
4. `prefers-reduced-motion: reduce`：直接状态切换。

每个环境检查：

- 起点是否与原图标、原标题完全重合。
- 运动过程中是否出现双影、闪烁、换行或透明断点。
- 终点是否与固定栏目标槽位完全重合。
- 反向滚动是否沿同一路径返回。
- 开始训练、编辑周计划和底部菜单点击是否正常。
- 页面控制台是否存在错误或警告。

输出以下验收材料到已忽略的 `output/playwright/`：

- 移动端正向与反向滚动视频。
- 移动端起点、中间态、终点截图。
- 桌面端终点截图。

## 8. 风险与控制

- **文本缩放后发虚**：固定状态仍使用同一共享层；验证 Chromium 是否重新栅格化。若终点持续发虚，仅在元素完全静止且像素级重合后做无感接管，不在运动过程中交叉淡入。
- **字体加载导致测量偏移**：等待 `document.fonts.ready` 后重测，并由 `ResizeObserver` 兜底。
- **滚动时掉帧**：滚动帧内不读取布局，不写 React state，不动画布局属性。
- **快速滚动越过阶段**：所有视觉状态由当前进度纯计算，不依赖某一帧必须执行。
- **菜单切换后坐标失效**：返回今日页时强制重置进度并在下一帧测量。
- **长标题碰撞“今天 ·”**：目标槽位为标题预留最大宽度，最终状态单行省略；运动阶段不换行。
- **缩小图标细节密集**：先按规格保留完整图标；如果 `22px` 实测不可读，只允许减少内部低对比刻度，不更换图标身份。
