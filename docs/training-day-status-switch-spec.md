# 训练日状态开关交互规格

## 背景

计划页当前使用原生方形复选框表达 `enabled` 状态。绿色勾选容易被理解为“计划已确认”或“今天已经完成”，但它实际表示的是“这一天是否参与周计划并出现在今日训练”。业务逻辑本身保留，只重新设计状态表达和切换反馈。

## 目标

1. 用户能立即理解这是“当天安排”的状态，而不是保存、完成或确认动作。
2. 保留训练日必须包含动作、休息日可保留动作配置、添加动作自动启用训练日的现有规则。
3. 切换为休息日时，不让用户误以为已有动作会被删除。
4. 不增加圆角卡片、边框框组或多余分割线，保持计划页现有视觉语言。

## 不在本次范围

- 不修改 `enabled` 字段、计划接口、今日计划筛选和训练快照逻辑。
- 不改变训练日必须至少包含一个动作才能保存的规则。
- 不重新设计动作编辑器、星期切换、保存栏或顶部共享元素动画。
- 不删除休息日中已经配置的动作。

## 状态控件

### 布局

状态控件继续位于训练日编辑头部右侧，与星期、训练名称和训练重点组成同一头部，但不使用方形勾选图标。

结构为：

```text
当天安排
训练日   [开关]
```

休息状态为：

```text
当天安排
休息日   [开关]
```

- “当天安排”使用低强调小字，只解释控件含义。
- “训练日 / 休息日”是当前状态结果，不使用“开启 / 关闭”这种脱离业务的文案。
- 开关采用标准横向轨道与滑块，不放进卡片或描边容器。
- 状态名称和开关构成一个不小于 `44px` 高的整体点击区域。
- 点击文字、轨道或滑块都执行同一个切换行为。

### 视觉状态

#### 训练日

- 状态文字使用正文亮色，开关轨道使用亮绿色。
- 滑块位于右侧。
- 星期栏保留训练日的低强调绿色状态点。

#### 休息日

- 状态文字和轨道使用低强调灰色，滑块位于左侧。
- 星期栏不显示训练状态点。
- 如果保留了动作，在状态控件下显示 `已保留 7 个动作`；没有动作时不显示这行说明。

## 交互规则

### 从休息日切换为训练日

1. 没有动作时立即切换，不弹确认层。
2. 页面显示现有空状态，引导添加第一个动作。
3. 保存栏提示 `训练日至少需要一个动作`，保存按钮保持不可用。
4. 如果休息日保留了动作，切换后这些动作立即生效，不需要二次确认。

### 添加动作

1. 在休息日添加动作时，沿用现有逻辑，自动切换为训练日。
2. 状态开关同步滑到训练日位置。
3. 不额外弹出提示或 Toast，避免打断连续编辑；控件本身的状态变化就是反馈。

### 从训练日切换为休息日

#### 没有动作

- 立即切换为休息日，不弹确认层。

#### 已有动作

- 第一次点击只打开确认层，不立即修改 `enabled`。
- 确认层文案：

```text
设为休息日？
已配置的 7 个动作会保留，重新启用训练日后仍可继续使用。
```

- 主操作：`设为休息日`。
- 次操作：`取消`。
- 点击遮罩、按 `Escape` 或执行取消均关闭确认层，状态保持训练日。
- 确认后设置 `enabled = false`，保留名称、重点和全部动作配置。

## 确认层

- 移动端使用靠近屏幕底部的轻量确认层；桌面端使用居中的紧凑确认层。
- 通过 portal 或原生 `dialog` 脱离计划页滚动容器，避免被 `overflow` 裁切。
- 不使用多条分割线、统计卡片或警告图标堆叠。
- 标题、说明和两个操作形成单一信息层级。
- 打开动画为约 `160ms` 的淡入与 `8px` 纵向位移，使用 ease-out；关闭略快。
- `prefers-reduced-motion: reduce` 下即时显示和关闭。

## 休息日保留动作

- 保留动作仍显示在编辑区并允许继续修改，不降低文字对比度，也不禁用表单。
- 状态控件下的 `已保留 N 个动作` 明确说明这些动作当前不会进入今日训练。
- 周导航仍显示“休息 / 未安排”，不把保留动作误报为有效训练计划。
- 再次切换为训练日后，保留说明消失，动作立即作为当天计划生效。

## 动效

- 开关滑块使用 `transform` 移动，轨道颜色同时过渡，时长约 `160ms`。
- 状态文字直接更新颜色和内容，不做左右飞入或缩放。
- `已保留 N 个动作` 使用短距离淡入，不改变编辑区滚动位置。
- 控件不参与计划页顶部固定栏的共享元素动画，随编辑头部自然滚出。

## 可访问性

- 控件使用真实 `button` 配合 `role="switch"`，或使用可定制但语义完整的 checkbox。
- 提供 `aria-checked`，可访问名称为 `当天安排：训练日` 或 `当天安排：休息日`。
- 键盘可通过 `Space` 和 `Enter` 切换。
- 焦点样式清晰，不只依赖颜色表达状态。
- 确认层打开后焦点进入主操作，关闭后返回状态开关。

## 验收标准

1. 页面不再出现容易被理解为“已完成”的绿色方形勾选框。
2. 用户能从“当天安排 + 训练日/休息日 + 开关”理解该控件的业务含义。
3. 添加第一个动作会自动切换为训练日。
4. 无动作训练日仍不能保存。
5. 有动作时切换为休息日必须确认，取消不会改变状态。
6. 确认切换后动作不会丢失，并显示准确的保留动作数量。
7. 重新启用训练日后，保留动作立即恢复生效。
8. 移动端点击区域不小于 `44px`，纵向滑动不会误触状态切换。
9. 确认层可通过遮罩、取消和 `Escape` 关闭，焦点行为正确。
10. TypeScript、ESLint、生产构建、现有测试和 `git diff --check` 全部通过。
