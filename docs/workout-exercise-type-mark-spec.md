# 训练页面动作类型水印图标规格

## 1. 背景

训练进行页的动作标题右侧目前固定展示力量感较强的杠铃水印图标。动作选择器已经将固定动作划分为力量、有氧、核心三类，因此训练进行页也需要根据当前动作类型切换对应图标，让用户在不阅读额外文字的情况下快速识别训练类型。

## 2. 已确认方案

采用“动能类型图标”方案：

- 力量：保留当前杠铃与负荷轨迹的视觉语义。
- 有氧：使用前倾跑者、橙色能量节点与三条交错向后穿梭的速度线，表达持续推进和耐力。
- 核心：使用现成 Dead Bug 完整动画，通过对侧手脚交替伸展表达核心稳定与控制。

三种标识共用低饱和亮绿、灰绿和橙色主题。类型差异主要依靠杠铃、跑步和核心训练动作表达，不依赖额外类型文字。

## 3. 目标

- 当前训练动作切换时，标题右侧水印自动切换为对应类型图标。
- 三种图标在同一套视觉语言下具有清晰、可辨认的差异。
- 保持现有训练页的信息层级、布局尺寸和暗色运动氛围。
- 保留现有动作数据结构和训练记录流程，不引入新的业务字段。

## 4. 不在本次范围

- 不调整重量、次数、时间、组数进度、训练提示和备注区域。
- 不调整训练页顶部动作导航、计时器和跳过动作功能。
- 不修改动作选择器的分类、搜索和选择交互。
- 不启用自定义动作，也不为自定义动作增加分类入口。
- 不修改 API、数据库或训练记录数据结构。
- 不改变其他页面使用的全局 `TrackMark` 品牌图标。

## 5. 类型来源与回退

训练页根据当前动作的 `exerciseId` 调用现有 `exerciseCategory(exerciseId)` 获取类型：

- `strength`：展示力量图标。
- `cardio`：展示有氧图标。
- `core`：展示核心图标。
- `null` 或未知 ID：展示当前力量水印作为兼容回退。

未知动作使用力量水印仅是视觉回退，不代表把该动作的数据类型判定为力量。未来开发自定义动作时，需要为自定义动作提供显式分类，再扩展这里的类型来源。

## 6. 通用视觉规范

- 力量继续使用 `64 × 48` 的 SVG `viewBox`；有氧和核心使用经过主题适配的专业 Lottie 完整时间轴。
- 继续复用 `.workout-watermark` 的位置、尺寸、透明度和响应式规则：
  - 桌面端约 `190 × 190px`。
  - 移动端约 `140 × 140px`。
- 主结构使用低饱和橄榄亮绿；力量与有氧统一使用 `#81A645`，速度线使用更灰的 `#71875C`，能量终点或头部使用低饱和橙色 `#BE6324`。
- 有氧 Lottie 不再叠加公共水印透明度，人物四肢统一使用同一亮绿色，橙色头部与速度线保持清楚可见。
- 核心 Lottie 同样不叠加公共水印透明度：人物使用亮绿和灰绿层级，橙色只强调腹部核心区域。
- 力量图标保留水印层级，但将总透明度提升到 `.48`，补偿低饱和配色在深色背景上的亮度损失。
- 描边使用圆角端点和圆角连接，线宽保持在约 `1.5–2.35` 之间。
- 力量图标保持线性、抽象、轻量；两种人物动画保持透明背景，均不增加背景卡片、类型文字或标签。
- 三种标识的视觉重量和留白比例应接近，避免某一类型明显更重或更空。
- 标识是装饰性信息，统一设置 `aria-hidden="true"`，不进入读屏顺序。

## 7. 三种图标造型

### 7.1 力量

- 保留当前图标的核心造型：左右杠铃片、中间杠杆、负荷变化轨迹和橙色终点。
- 视觉含义是阻力、负重和输出。
- 新组件中的力量图标应与当前训练页水印保持视觉一致。
- 如实现时抽取共用 SVG 结构，必须保证其他页面现有 `TrackMark` 的渲染结果和行为不变。

### 7.2 有氧

- 主体严格复用已确认设计稿中的向右前倾、迈步推进的极简跑者，不替换为通用跑步人形图标。
- 头部使用小面积橙色能量节点，身体和四肢使用荧光绿与灰绿色层级。
- 跑者身后保留三条交错穿梭的短速度线，表达向前移动，不增加大箭头。
- 造型保持轻量和器械无关，可覆盖跑步机热身、爬坡走以及未来的其他移动型有氧动作。
- 不使用椭圆跑道、胶囊外轮廓、心率脉冲或完整跑步机轮廓。

### 7.3 核心

- 主体使用 LottieFiles 的 `Deadbug fitness exercise` 完整人物动画。
- 保留源动画中仰卧、对侧手脚交替伸展和受控回收的动作关系。
- 人物主体使用低饱和亮绿与灰绿，橙色仅位于腹部和躯干核心区域。
- 不重画人体、不重新拼接关节，也不在源时间轴上叠加自制肢体动画。
- 不增加速度线、目标环或抽象汇聚轨迹。
- 具体动作、配色、节奏、来源和许可见 `docs/core-trainer-motion-spec.md`。

## 8. 动效规范

- 动效保持在图标局部，不引起标题区布局变化。
- 力量：负荷轨迹沿现有方向轻微流动。
- 有氧：双臂使用“肩—肘—手”连续路径，双腿使用“髋—膝—踝—脚”连续路径；半个周期后前后肢体完成换位，关节连接点由同一组关键帧共享，不得出现断线；人物随落脚轻微回弹，橙色头部在原位缩放和明暗呼吸，三条速度线清楚地向后流动。
- 核心：保留现成 Dead Bug 源动画的完整时间轴，以 `0.85` 倍速完成约 `7.1s` 的受控正向循环；不增加逐帧变色、呼吸亮度或速度线。
- 有氧步态保留现成源动画的完整时间轴，统一驱动肩、肘、髋、膝和躯干；播放器以 `0.72` 倍速循环，头部呼吸与速度线在同一时间轴内同步。力量继续沿用约 `1.45s` 的节奏。
- 切换动作时直接切换对应 SVG 或 Lottie，不增加额外的页面级转场。
- 当系统开启 `prefers-reduced-motion: reduce` 时：
  - 停止所有路径、跑者、速度线和节点动画。
  - 展示完整静态图形与节点。
  - 不影响类型辨识。

## 9. 组件边界

新增训练类型图标组件，建议接口如下：

```ts
type ExerciseTypeMarkProps = {
  category: ExerciseCategory | null;
  className?: string;
  state?: "idle" | "syncing";
};
```

组件职责：

- 根据 `category` 渲染力量 SVG、有氧 Lottie 或核心 Lottie。
- 统一处理公共类名、动画状态、装饰性无障碍属性和未知类型回退。
- 仅在训练进行页替代当前水印入口。

组件不负责：

- 推断或修改动作类型。
- 变更当前动作和训练进度。
- 写入训练数据。
- 替换全局品牌 `TrackMark`。

具体的有氧与核心文件拆分、资源生成和验证顺序分别见
`docs/cardio-runner-motion-implementation-plan.md` 与
`docs/core-trainer-motion-implementation-plan.md`。

## 10. 响应式与布局

- 保持当前标题区水印的绝对定位，不改变标题、动作名称和组数信息的排版。
- 桌面端与移动端均不得遮挡动作标题的主要可读区域。
- 长动作名称换行时，图标仍作为低透明度背景存在，不抢占文本布局宽度。
- 移动端沿用当前水印的缩小和右移规则，不新增横向滚动。

## 11. 验收标准

- 力量动作展示力量图标，视觉上延续当前杠铃水印。
- 跑步机热身、爬坡等有氧动作展示有氧图标。
- 平板支撑、死虫、卷腹等核心动作展示核心图标。
- 在训练页切换到上一个或下一个动作后，图标随当前动作立即更新。
- 三种类型仅通过造型即可区分，关闭颜色后仍能辨认。
- 三种标识使用相同的主题色和一致的视觉重量，并适配同一个水印区域。
- 未知动作 ID 不报错，并回退到当前力量水印。
- 回退不修改动作数据，也不把未知动作写为力量类型。
- 训练页的计时、组数、重量、次数、完成状态和保存行为保持不变。
- 其他页面现有 `TrackMark` 的外观和动画保持不变。
- 自定义动作入口仍不展示，本次不新增相关字段或交互。
- 桌面端和移动端均无明显遮挡、溢出或布局跳动。
- 开启减少动态效果后，图标静态可见且无路径动画。
- TypeScript、lint、相关测试和生产构建通过。

## 12. 主要风险与约束

- 有氧跑者比抽象跑道更易识别，但对单车、划船等非跑步动作的覆盖较弱；当前固定有氧动作以跑步机热身和爬坡为主，因此本轮优先保证当前场景辨识度。
- Dead Bug 对核心稳定的表达比抽象图形明确，但原始画板横纵比和人物动作幅度较大，接入时必须重点检查移动端缩放、边缘裁切和右侧留白。
- 直接修改 `TrackMark` 可能影响全局品牌图标，因此训练类型图标应保持独立边界。
- 当前固定动作均有明确分类；未知 ID 的回退仅用于兼容旧数据和为后续自定义动作预留安全路径。
