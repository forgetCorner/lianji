# 移动端液态玻璃菜单规格

## 1. 背景与目标

当前移动端底部导航使用固定深色栏和四个独立按钮，点击可以切换“今日 / 计划 / 排行 / 我的”，但选中反馈仍是普通的图标与文字变色。

本次把移动端选中状态升级为接近 iOS 系统分段菜单的液态玻璃浮层：

- 手指按下后，玻璃选中层立即响应当前触点。
- 按住左右滑动时，玻璃层跟随手指并磁吸到最近菜单。
- 松手后才提交最终页面切换。
- 视觉保持练迹的深色、低饱和绿色主题，不照搬高亮白色 iOS 皮肤。

## 2. 已确认方向

采用“方案 A：拖动预览，松手切页”。

- 导航仍包含“今日 / 计划 / 排行 / 我的”四项，顺序和业务入口不变。
- 当前页面对应一个可移动的液态玻璃选中层。
- 点击菜单仍可直接切换。
- 长按并左右滑动时，选中层自动吸附到最近菜单中心。
- 滑动过程中只更新视觉预览，不修改当前页面。
- 松手时只执行一次页面切换，并沿用现有左右页面转场方向。

不采用“滑过即切页”，避免手指经过中间菜单时连续挂载多个页面、触发滚动状态变化或产生闪烁。

## 3. 修改范围

仅修改移动端主导航：

- 生效范围：`max-width: 760px`。
- 生效页面：已登录且当前不是训练进行页。
- 菜单项：今日、计划、排行、我的。
- 桌面端侧边导航保持现状。
- 训练进行页继续隐藏底部导航。
- 账号、训练、计划、排行、历史记录等业务数据和接口不变。
- 页面本身的共享元素、滚动吸顶和内容动画不在本次调整。

## 4. 视觉结构

### 4.1 导航底座

- 底部导航从通栏实色背景调整为悬浮式深色玻璃底座。
- 底座保留安全区适配，不能压住 iPhone Home Indicator。
- 底色以深灰绿半透明层为主，叠加克制的模糊和饱和度。
- 边缘使用一条低对比度半透明描边，顶部高光比底部更清楚。
- 阴影只负责与页面背景分层，不制作明亮悬浮卡片。

### 4.2 液态玻璃选中层

选中层位于按钮内容下方、导航底座上方：

- 基础形态是带圆角的透明玻璃胶囊，宽度接近单个菜单槽。
- 内部包含极弱的亮绿着色、上缘高光、中心透亮区和底部暗部。
- 玻璃层必须允许看到其后的背景色变化，不能退化成不透明绿色按钮。
- 选中图标与文字使用练迹亮绿，未选中项继续使用低强调灰绿。
- 玻璃层本身不增加文字、描边图标或额外状态点。

### 4.3 按压与拖动形变

- 按下时玻璃层轻微压缩高度并横向扩张，形成柔软受力感。
- 拖动时玻璃层中心跟随触点，但会被最近菜单中心持续吸引。
- 快速拖动时允许轻微横向拉伸，拉伸方向与速度一致。
- 接近目标中心后拉伸逐渐收回，不在吸附完成后持续抖动。
- 松手后使用短促弹簧回到目标菜单的标准尺寸。
- 图标与文字不跟随玻璃形变拉伸，保持清晰。

## 5. 交互规则

### 5.1 点击

1. 点击任一菜单项。
2. 玻璃层移动到目标菜单。
3. 页面只切换一次。
4. 已处于目标页面时不重复切页，只播放轻微按压回弹。

### 5.2 按住与滑动

1. 主指针按下时记录起点、当前页面索引和四个菜单中心位置。
2. 导航获取 pointer capture，保证手指移动到按钮间隙时仍能继续拖动。
3. 玻璃层先响应触点所在的最近菜单，随后跟随横向移动。
4. 预览目标按触点到四个菜单中心的距离计算。
5. 在相邻菜单分界处保留少量迟滞区，避免手指轻微抖动导致目标反复横跳。
6. 松手时提交当前预览目标；如目标未变化，不触发页面更新。
7. `pointercancel`、失去捕获或组件卸载时回到已提交页面，不产生半停留状态。

### 5.3 横纵手势边界

- 导航区域主要识别水平拖动。
- 纵向移动明显大于横向移动时取消菜单拖动，让系统保持自然的纵向手势语义。
- 不阻止页面主体正常滚动。
- 不拦截浏览器边缘返回手势。
- 只响应主指针和单指触摸，不处理多指手势。

### 5.4 页面提交

- 拖动期间不调用现有 `navigateView`。
- 松手后调用一次 `navigateView(targetView)`。
- 现有 `menuViews` 顺序继续决定页面转场方向。
- 页面切换后，玻璃层的已提交位置与当前 `view` 同步。
- 外部逻辑改变 `view` 时，玻璃层自动移动到正确菜单，不保留过期预览。

## 6. 动效参数

第一版使用以下节奏作为实现基线，实际可在浏览器验收时小幅调整：

- 按下反馈：`90–120ms`。
- 玻璃跟手：不使用固定补间，直接更新位置并加入有限阻尼。
- 最近菜单吸附：约 `140–180ms` 的短弹簧。
- 松手归位：约 `180–240ms`，无明显二次反弹。
- 点击切换：约 `180–220ms`。
- 最大横向拉伸：标准宽度的 `6%–10%`。
- 最大纵向压缩：标准高度的 `4%–7%`。

动效重点是“跟手、吸附、回弹”，不能出现漂浮过慢、橡皮筋拉得过长或玻璃层在菜单间来回晃动。

## 7. 技术方案

### 7.1 组件边界

把移动端导航交互封装为独立组件或独立 Hook，避免在 `Home` 中堆叠手势细节。

建议状态：

```ts
type MobileNavView = "today" | "plan" | "ranking" | "profile";

type DragState = {
  pointerId: number;
  startX: number;
  startY: number;
  currentX: number;
  previewIndex: number;
  dragging: boolean;
};
```

组件接收：

```ts
type MobileNavProps = {
  view: View;
  setView: (view: View) => void;
};
```

组件内部负责：

- 菜单几何测量。
- pointer capture 生命周期。
- 拖动预览索引。
- 点击抑制，避免拖动松手后再触发一次 `click`。
- 玻璃层位置、形变和动画值。
- 无障碍与降级处理。

`Home` 继续只负责提供当前 `view` 和现有 `navigateView`。

### 7.2 动画实现

- 复用项目现有 `motion/react`，不新增动画依赖。
- 用 Motion value 或等价的受控 transform 驱动玻璃层 `translateX / scaleX / scaleY`。
- 位置和尺寸只使用 transform，避免拖动期间触发布局重排。
- 菜单中心只在按下、视口变化和导航尺寸变化时重新测量，不在每一帧读取布局。
- 使用 CSS `backdrop-filter`、渐变、伪元素和阴影完成玻璃质感，不引入 Canvas 或 WebGL。

### 7.3 CSS 降级

- 支持 `backdrop-filter` 时展示完整模糊玻璃。
- 不支持时使用更高不透明度的深灰绿底色、边框与高光，保证仍可辨认。
- `prefers-reduced-transparency: reduce` 下减少透明与模糊，改用稳定的深色选中层。
- `prefers-reduced-motion: reduce` 下取消拉伸和弹簧，选中层直接定位到目标菜单。

## 8. 可访问性

- 四个入口继续使用真实 `button`。
- 当前页面继续通过 `aria-current="page"` 表达。
- 玻璃层设置 `aria-hidden="true"`，不进入读屏顺序。
- 键盘、Switch Control 或其他非指针操作继续通过按钮点击直接切换。
- 焦点样式不能被玻璃层遮挡。
- 单个菜单触控区域不小于 `44 × 44px`。
- 选中状态不能只依赖玻璃透明度；图标和文字颜色同步变化。

## 9. 风险与处理

### 手势与点击重复触发

拖动结束后浏览器可能继续派发 `click`。组件需要记录是否发生有效拖动，并只抑制该次后续点击，不能破坏下一次正常点击。

### iOS Safari 指针事件中断

必须覆盖 `pointercancel`、`lostpointercapture` 和窗口尺寸变化；任何中断都回到当前页面对应位置。

### 玻璃效果在深色背景上不明显

通过边缘高光、内层明暗和微弱绿色折射建立层次，不依赖单纯提高背景亮度。

### 页面被连续切换

拖动阶段只更新预览，松手只提交一次，避免重复挂载页面和触发接口或滚动副作用。

### 固定底栏与安全区

继续使用现有 `--mobile-nav-height` 与 `env(safe-area-inset-bottom)`，浮层不能超出可交互区域或遮挡系统 Home Indicator。

## 10. 验收标准

1. `760px` 以下显示新的悬浮玻璃底部导航，桌面侧边栏完全不变。
2. 今日、计划、排行、我的四项顺序和点击功能保持不变。
3. 当前菜单下方有清楚但克制的液态玻璃选中层。
4. 手指按下时玻璃层立即产生轻微压缩和横向扩张。
5. 按住左右滑动时玻璃层跟手，并自动吸附到最近菜单。
6. 在相邻菜单边界轻微抖动时，预览目标不会快速来回跳变。
7. 拖动途中页面不切换，松手后只切换到最终菜单一次。
8. 从右向左和从左向右切换时，现有页面转场方向正确。
9. 快速滑动、慢速拖动、按下后取消和滑出导航区域均不会留下半停留状态。
10. 拖动后不会额外触发一次点击，普通点击也不会被误拦截。
11. iPhone 安全区下底栏和 Home Indicator 不重叠。
12. 训练进行页仍不展示底部菜单。
13. `prefers-reduced-motion: reduce` 下无拉伸和弹簧动画。
14. 减少透明或不支持 `backdrop-filter` 时仍有清楚的选中状态。
15. 四个按钮的 `aria-current`、键盘操作和焦点样式保持正确。
16. TypeScript、ESLint、相关测试、生产构建和移动端真实浏览器手势验收全部通过。
