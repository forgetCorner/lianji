# “我的”页面近期训练重设计实施计划

> 对应规格：[`profile-recent-workouts-redesign-spec.md`](./profile-recent-workouts-redesign-spec.md)
>
> 规格状态：已确认
>
> 本计划只覆盖“我的 → 近期训练”，不修改头部动画、顶部统计、训练频率和力量趋势。

## 实施目标

在不改变后端数据和记录顺序的前提下，把近期训练从当前“日期 + 内容”结构改为带现有时间线的三列账页式布局：

1. 日期列：`MM.DD` + 中文星期。
2. 训练名称列：名称 + 组数和时长。
3. 训练容量列：容量数值 + “训练容量”标签。

三列第一层按绿、橙、蓝循环着色，第二层保持默认弱化色。训练名称换行时，中间和右侧第二层共享同一行高并底部对齐。

## 改动文件

| 文件 | 计划改动 |
| --- | --- |
| `app/page.tsx` | 重组近期训练 JSX、格式化日期和星期、删除重复 footer |
| `app/globals.css` | 实现三列两行网格、循环强调色、时间线终点和移动端适配 |
| `tests/rendered-html.test.mjs` | 增加结构、颜色范围、零容量和 footer 删除的回归断言 |

不修改 `lib/server/dashboard.ts`、数据库结构和其他组件。

## 任务 1：重组近期训练结构

### 文件

- `app/page.tsx`

### 实施内容

1. 保留 `dashboard.recentWorkouts.map((session, index) => ...)` 和当前绿、橙、蓝类名循环。
2. 将日期格式从“日 + 英文月份”改为：
   - 第一层：两位月份和日期组成的 `MM.DD`。
   - 第二层：根据本地日期计算的 `周日` 至 `周六`。
3. 使用确定性的月份、日期和星期格式化，不依赖不同运行环境可能产生差异的英文月份缩写。
4. 将每条记录拆成清晰的同级网格项：
   - 时间线状态点。
   - `time.session-date`。
   - `h3.session-name`。
   - `strong.session-volume`，其中数字和 `kg` 保持同一行。
   - `p.session-meta`，显示组数与时长。
   - `span.session-volume-label`，固定显示“训练容量”。
5. 容量始终使用 `formatNumber(session.volume_kg)`：
   - `0` 正常输出 `0 kg`。
   - 不增加容量与时长之间的条件分支。
6. 保留当前空状态内容和 `History` 图标。
7. 删除近期训练底部的“累计 N 次训练 · 已云端同步” footer。

### 结构约束

- 不给记录增加点击事件、按钮、箭头或详情语义。
- 不修改 `WorkoutSummary` 类型和 `DashboardData`。
- 不改动相邻的训练频率和力量趋势 JSX。
- 时间线状态点继续使用装饰性元素，并设置或保留 `aria-hidden`。

## 任务 2：实现三列两行布局

### 文件

- `app/globals.css`

### 桌面与通用布局

1. 将 `.session` 改为共享两行的三列网格：
   - 日期列使用稳定宽度。
   - 训练名称列使用 `minmax(0, 1fr)`。
   - 容量列按内容宽度占位并右对齐。
2. 日期容器跨越网格两行，内部保持“日期 + 星期”的现有上下组合。
3. 训练名称和容量位于第一行，并分别顶部对齐。
4. 组数与时长、容量标签位于第二行：
   - 由第一行最高内容统一撑开第二行位置。
   - 两者使用一致行高并底部对齐。
5. 训练名称自然换行，不能通过绝对定位或固定高度伪造对齐。
6. 容量数字和 `kg` 使用 `white-space: nowrap`，避免单位掉到下一行。
7. 删除旧 `.timeline footer` 样式。

### 时间线

1. 保留 `.session::before` 中性连接线和 `.session > i` 状态点。
2. 状态点继续跟随绿、橙、蓝循环色。
3. 最后一条记录隐藏向下延伸的连接线。
4. 只有一条记录时只显示状态点。
5. 不引入视觉稿中的心电图图标。

### 颜色

1. 为每条 `.session` 定义统一的记录强调色变量：
   - 默认 / `.lime`：`var(--lime)`。
   - `.orange`：`var(--orange)`。
   - `.blue`：`var(--blue)`。
2. 强调色只应用到：
   - 状态点。
   - `.session-date strong`。
   - `.session-name`。
   - `.session-volume` 及其 `kg` 单位。
3. `.session-date small`、`.session-meta` 和 `.session-volume-label` 始终使用弱化色。
4. 不修改全局主题变量，也不影响排行榜等其他绿、橙、蓝规则。

### 移动端

1. 在现有 `@media (max-width: 760px)` 中只增加近期训练所需的列宽、间距和字号覆盖。
2. 优先保证 `375px` 内容宽度下：
   - 日期列不压缩。
   - 容量列不换行。
   - 名称列可以自然换行。
3. 长名称只增加当前记录高度，不通过横向滚动解决。
4. 不改动 `.profile-progress-columns` 的单列顺序、`.app-content` 滚动模型和底部菜单空间。

## 任务 3：增加结构回归测试

3. 容量直接使用 `formatNumber(session.volume_kg)` 并固定展示 `kg`。
4. 页面中不存在针对零容量切换到时长的条件分支。
5. 原重复 footer 文案“累计 ... 次训练 / 已云端同步”不再属于近期训练结构。
6. `.session` 使用三列两行网格，名称列允许收缩。
7. 绿、橙、蓝类通过记录强调色变量控制第一层和状态点。
8. 第二层样式明确使用弱化色，不继承记录强调色。
9. 最后一条记录不继续绘制连接线。

保留现有训练统计、头部、训练频率和力量趋势断言，不为通过新测试而放宽旧测试。

- 容量是否始终顶部对齐且不换行。
- 最后一条记录下方是否没有多余时间线。
- 页面是否没有横向滚动和内容遮挡。
- 头部动画、训练频率和力量趋势是否保持原样。

视觉验收只使用现有真实记录和安全的只读页面状态，不修改或伪造云端训练数据。

## 风险与控制

### 长名称挤压容量

- 风险：名称列过窄时，容量数字可能与名称重叠。
- 控制：名称列使用 `minmax(0, 1fr)`，容量列禁止换行，名称负责自然换行。

### 第二层错位

- 风险：中间和右侧各自使用内部堆叠时，两行名称会再次造成截图中的错位。
- 控制：中间备注和右侧标签必须是同一个外层网格的第二行项目，不能放在两个互不关联的纵向容器中。

### 循环色污染备注

- 风险：给整条 `.session` 设置 `color` 会让第二层一起变色。
- 控制：记录强调色通过自定义变量只赋给明确的第一层选择器，第二层显式指定弱化色。

### 时间线延伸过长

- 风险：删除 footer 后，最后一条伪元素仍向下延伸。
- 控制：增加最后记录选择器，单条和多条状态都停止末端连接线。

### 影响相邻模块

- 风险：复用过宽的后代选择器会误伤力量趋势或全局标题。
- 控制：所有新增选择器限定在 `.timeline .session` 或明确的 `session-*` 类名下。
