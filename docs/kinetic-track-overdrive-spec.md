# 练迹「动能轨道」Overdrive 视觉与动效规格

> 状态：已确认
>
> 方向：A「动能轨道」
>
> 适用范围：应用外壳、启动过程、今日、计划、排行、我的与关键反馈状态

## 1. 改造目标

本次不是在现有页面上继续增加零散线条，而是建立一套完整、可辨认、可持续扩展的“力量场”视觉系统。

需要同时解决四个问题：

1. 启动动画过短，刷新时几乎不可感知。
2. 现有品牌图标尺寸小、线条轻，缺少力量和记忆点。
3. 背景只有低透明轨迹，无法形成有纵深的视觉环境。
4. 图标、状态图形和交互反馈各自独立，没有统一的运动规律。

改造完成后，首次打开应产生明确的“这不是普通记录工具”的第一印象；进入页面后，主要操作仍然快速、清楚，不让持续特效干扰训练记录。

## 2. 核心概念

### 2.1 物理场景

用户在光线偏暗的训练环境中打开练迹，设备像一套记录力量输出的仪器被唤醒：能量沿训练轨迹汇聚，杠铃结构锁定，随后整个训练空间被点亮。

### 2.2 视觉关键词

- 动能
- 轨迹
- 锁定
- 冲击
- 精密刻度
- 真实训练数据

### 2.3 动效原则

- 只有一个主奇观：启动时的“能量汇聚与标志锁定”。
- 页面内动效表达状态和反馈，不持续争夺注意力。
- 所有运动都遵循“汇聚 → 锁定 → 推进”的同一物理规律。
- 不使用随机彩色粒子、烟花、弹跳、果冻或游戏升级特效。
- 不增加自动播放声音；未来如增加声音，必须由用户主动开启。

## 3. 视觉系统

### 3.1 色彩角色

保留现有深色底、草绿和橙色识别，但重新规定用途：

| 角色 | 用途 |
| --- | --- |
| 近黑底色 | 应用空间和启动遮罩 |
| 深灰绿 | 网格、器械结构、非激活轨迹 |
| 草绿色 | 主能量、当前状态、可执行动作 |
| 橙色 | 运动前端、冲击点、警告和中断位置 |
| 米白色 | 标题、主要数据和稳定结构 |

草绿色不大面积铺满页面。高亮由亮度、运动和空间层级共同建立，不依赖高饱和色块。

### 3.2 品牌标志 2.0

现有细线“横杆 + 折线”升级为更有重量的几何标志：

- 左右两端由双层杠铃片形成稳定锚点。
- 中间横杆是完整结构，不再像普通折线图。
- 横杆中心嵌入向右上推进的力量轨迹。
- 轨迹终点使用橙色能量核。
- 小尺寸版允许减少内部细节，但外轮廓必须保持一致。

标志包含三个标准状态：

1. **静止**：完整、稳定，无持续动画。
2. **激活**：轨迹亮起，橙色能量核向前移动一次。
3. **同步**：能量核在最后一段轨迹中低频巡航。

应用位置：

- 启动动画主视觉：`112–148px`
- 桌面侧边栏：`44px`
- 手机导航或账号入口：`28–32px`
- favicon：简化静态版

### 3.3 自定义图标体系

不继续混合普通线性图标与临时 SVG。建立同一结构语言的图标组：

- 今日：交叉哑铃与能量节点
- 计划：七段训练轨道与日历定位点
- 排行：向上汇聚的三条进步轨迹
- 我的：围绕中心点的个人训练环
- 连续训练：燃烧轨迹，不使用普通火焰轮廓
- 本周状态：七段机械刻度
- 好友进步：双轨汇聚标记
- 保存：轨迹锁定符号
- 开始训练：向前推进的能量箭头
- 恢复：未闭合的缓慢能量环

每个导航图标至少包含默认、悬停和激活三态。激活动画控制在 `180–260ms`，不做永久循环。

## 4. 启动动画：动能点火

### 4.1 触发规则

- 浏览器首次打开和每次完整刷新时播放。
- 今日、计划、排行和我的之间切换不播放。
- 打开弹层、完成一组训练和从后台恢复不播放。
- 启动过程与真实账号检查、数据同步状态绑定，不显示虚假百分比。

### 4.2 正常时序

完整视觉时长约 `2.0–2.2s`，其中页面仍在后台并行加载。

| 时间 | 画面 |
| --- | --- |
| `0–180ms` | 全黑空间出现极弱的中心网格和器械刻度，橙色能量核点亮。 |
| `180–620ms` | 细碎粒子被能量核吸引，形成一条向中心高速推进的轨迹；远处轨迹产生轻微视差。 |
| `620–1050ms` | 左右杠铃片从粒子云中构成并向中心锁定，横杆被点亮。 |
| `1050–1320ms` | 品牌轨迹完成，橙色能量核落到终点；锁定瞬间产生一圈冲击波和短促刻度震荡。 |
| `1320–1680ms` | 完整品牌标志悬停，显示真实状态文字“正在同步训练轨迹”或“训练轨迹已就绪”。 |
| `1680–2100ms` | 标志向左上角移动并缩放为侧边栏品牌；中心能量线向两侧扫开页面，内容按层级显现。 |

快速加载也至少完成到“标志锁定”，避免再次出现刷新时看不到动画的问题。推荐最短可见时长为 `1.75s`，完整揭幕约 `2.1s`。

### 4.3 慢加载

如果真实数据在 `1.68s` 时仍未完成：

- 完整标志停留在中央。
- WebGL 力量场保持低速运动。
- 橙色能量核沿末段轨迹巡航，每次间隔不少于 `1.4s`。
- 状态文字在“正在检查账号”“正在同步训练轨迹”之间跟随真实流程切换。
- 数据就绪后直接进入最后的页面揭幕阶段，不重播开场。

### 4.4 错误状态

- 能量轨迹在故障点断开，断点变为橙色。
- 粒子运动在 `200ms` 内减速停止。
- 中央显示具体错误信息和“重新同步”按钮。
- 重试后从断点重新点火，不重播完整的杠铃装配过程。

### 4.5 未登录状态

- 动画完成品牌锁定后揭幕登录界面。
- 登录不是错误状态，不出现断裂轨迹。
- 登录弹层继承力量场背景，但输入和按钮保持标准表单交互。

## 5. 实时力量场背景

### 5.1 构成层级

背景使用一个全屏 WebGL Canvas，叠加少量 DOM/SVG 信息层，共五层：

1. **空间底层**：近黑色空间与非常缓慢的明暗呼吸。
2. **力量网格**：随视角轻微弯曲的坐标网格，表达训练空间而不是通用科技点阵。
3. **轨迹流**：少量长轨迹横向穿过页面，速度和方向与当前页面状态相关。
4. **能量粒子**：集中分布在主轨迹附近，不铺满整个屏幕。
5. **数据标记**：DOM/SVG 绘制的刻度、训练节点和状态坐标，保证清晰度。

### 5.2 页面状态

- **今日**：力量场最完整，轨迹在标题和今日状态之间形成主视线。
- **计划**：背景切换为训练序列图，七天节点像机械编排轨道一样展开。
- **排行**：三条进步轨迹向同一基线汇聚，强调相对进步而不是绝对重量。
- **我的**：背景简化为个人轨迹年轮，围绕训练频率和力量趋势缓慢旋转。
- **训练进行中**：背景明显降噪，仅在组完成和休息开始时释放短促能量反馈。

页面切换通过 `600–800ms` 的参数插值完成，Canvas 不重新挂载，不闪白、不重播启动动画。

### 5.3 鼠标与触摸响应

- 桌面端鼠标移动使附近轨迹产生最大 `6–10px` 的磁场偏移。
- 移动速度越快，橙色能量核拖尾越明显，但在停止后 `400ms` 内归位。
- 手机端不持续读取陀螺仪，不申请设备权限；改用固定缓慢视差。
- 背景始终 `pointer-events: none`，不阻碍页面操作。

## 6. 页面视觉升级

### 6.1 今日

- 恢复日主图升级为大型“恢复核心”：双层能量环、中心训练轨迹、当前橙色节点。
- 训练日显示 A/B/C 计划核心，字母与器械结构融合，不是简单把字放入圆圈。
- 本周进度线在页面揭幕时被逐段点亮。
- 计划行悬停时，能量从星期标签流向开始按钮，表达明确的操作方向。
- 没有训练记录时，以一条尚未点亮的轨迹表达“等待第一组”，不增加卡片。

### 6.2 计划

- 七天列表改为连续训练轨道，训练日节点比休息日节点更有重量。
- 切换日期时，当前节点沿轨道移动到目标日期，编辑区使用方向一致的内容过渡。
- 动作排序按钮悬停时显示短促机械位移；真正调整顺序后轨迹重新连接。
- 保存成功时，页面底部出现一次“轨迹锁定”，不使用普通绿色 toast 作为唯一反馈。

### 6.3 排行

- 排名不是奖牌卡片，而是三条或多条从个人基线出发的进步轨迹。
- 当前用户轨迹拥有更明显的能量核和基线标记。
- 切换时间范围时，轨迹长度和排序平滑重算，姓名位置不瞬间跳变。
- 仍然展示排名方法和稳定性，不用动画制造虚假成绩。

### 6.4 我的

- 训练频率、近期训练和力量趋势仍是唯一内容。
- 年度训练频率成为主视觉“轨迹年历”，训练日期点亮后向周围产生极弱波纹。
- 力量趋势首次进入视口时绘制一次；后续筛选只做数据形变，不重复入场表演。
- 个人档案和账号设置弹层使用品牌标志锁定过渡，不增加背景卡片。

### 6.5 训练与休息

- 完成一组：按钮能量向进度轨道传递，目标组节点被锁定。
- 完成动作：动作名称旁出现一次短促冲击环，下一动作从轨迹前方进入。
- 休息计时：圆环改为更有层次的双轨倒计时，进度变化必须清晰，不依赖颜色。
- 完成整次训练：允许一次最明显的页面内庆祝——轨迹贯通与粒子向外释放，持续不超过 `900ms`。

## 7. 动效层级与时长

| 层级 | 场景 | 时长 |
| --- | --- | --- |
| 主奇观 | 启动点火与页面揭幕 | `1.75–2.2s` |
| 页面过渡 | 今日、计划、排行、我的 | `600–800ms` |
| 状态变化 | 日期、筛选、弹层、训练步骤 | `220–420ms` |
| 即时反馈 | 按下、悬停、选中、锁定 | `100–220ms` |
| 完成庆祝 | 完成整次训练 | `700–900ms` |

缓动使用 `ease-out-quart`、`ease-out-quint` 和阻尼较高的 spring。禁止 bounce 和 elastic。

## 8. 技术方案

### 8.1 渲染职责

- **OGL / WebGL**：全屏力量网格、轨迹流、粒子、冲击波和视差。
- **Motion**：启动时间轴、SVG 标志、页面共享元素、列表和状态过渡。
- **SVG**：品牌图标、导航图标、状态图形和精确刻度。
- **CSS**：颜色、布局、静态降级、焦点和简单按钮反馈。

WebGL Canvas 作为独立的客户端组件动态加载，不参与服务端渲染，不访问训练业务数据。

### 8.2 状态接口

力量场只接收有限的视觉状态：

- `mode`: `boot | today | plan | ranking | profile | workout | rest`
- `intensity`: `idle | active | success | error`
- `progress`: `0–1`
- `accent`: `lime | orange`

组件不直接发请求，也不修改账号、计划、训练或排行榜数据。

### 8.3 启动状态机

沿用真实状态：

- `checking`
- `syncing`
- `ready`
- `error`

视觉时间轴和数据状态分离：数据可以提前完成，但揭幕不能早于最短可见时长；数据较慢时，动画进入稳定等待态。

## 9. 性能预算

- 桌面目标：常规交互保持 `60fps`，验收底线不低于 `50fps`。
- 手机目标：常规交互保持 `50–60fps`，低性能设备自动降低特效。
- Canvas DPR 上限：桌面 `1.5`，手机 `1.25`。
- 粒子建议数量：桌面 `120–180`，手机 `36–60`。
- 同屏高亮长轨迹不超过 `6` 条。
- 页面处于后台时暂停渲染循环。
- Canvas 不可见或训练输入获得焦点时降低刷新频率。
- WebGL 初始化失败时自动使用静态 SVG 力量场，不显示空白背景。
- 不加载 3D 模型、视频、GIF 或音频资源。

## 10. 响应式

### 桌面

- 完整力量场、鼠标磁场和页面参数过渡。
- 启动标志最大 `148px`。
- 允许多层刻度和远景轨迹。

### 平板

- 粒子数量降低约 `35%`。
- 隐藏远景数据标记，保留主轨迹和冲击反馈。
- 页面过渡不使用大范围模糊。

### 手机

- 粒子数量降低约 `65%`。
- 使用固定视差，不跟踪设备方向。
- 启动标志最大 `112px`。
- 背景只保留力量网格、主轨迹和少量能量核。
- 训练输入和主要按钮始终位于视觉特效之上。

## 11. 可访问性与降级

- `prefers-reduced-motion: reduce` 下不播放粒子汇聚、视差、页面扫开和冲击波。
- 减少动态模式使用静态完整标志、力量场背景和 `120ms` 交叉淡入，仍保持视觉品质。
- 所有 Canvas 和装饰 SVG 从读屏顺序中隐藏。
- 加载、错误、同步和完成状态保留可读文字，不只依赖动画或颜色。
- 键盘焦点始终位于特效层上方，轮廓对比度满足 WCAG AA。
- 动画不得改变按钮实际点击区域，也不得阻断输入。

## 12. 不在本次范围

- 不修改训练计划、排行榜、账号和同步接口。
- 不增加声音、视频、GIF 或外部图片素材。
- 不加入 3D 杠铃模型和完整游戏场景。
- 不增加会员、动态、成就商城或虚假训练数字。
- 不为每个普通文本段落增加独立入场动画。

## 13. 验收标准

1. 在正常网络下刷新页面，用户可以清晰看到能量汇聚、标志锁定和页面揭幕，不能再出现“没有动画”的感受。
2. 启动动画最短可见时长不低于 `1.75s`，内部导航不重复播放。
3. 新品牌标志在 `32px`、`44px` 和大尺寸启动状态下都能辨认出杠铃与推进轨迹。
4. 今日、计划、排行和我的拥有同一力量场，但能通过轨迹结构区分页面状态。
5. 今日页恢复日与训练日都有完整的大型状态核心，不再出现简单圆圈或大面积空白。
6. 导航与关键操作使用统一自定义图标，激活、悬停和默认状态一致。
7. 页面切换不闪白、不重新创建启动动画，不影响表单和训练记录操作。
8. 桌面 `1440px`、平板 `768px`、手机 `390px` 下无横向溢出或控件遮挡。
9. 中端手机的持续渲染不低于 `50fps`；如果低于底线，必须自动降级粒子和模糊层。
10. WebGL 不可用时，静态 SVG 背景、图标和所有业务功能仍可正常使用。
11. 减少动态模式下没有明显位移、视差和循环动画，但视觉层次仍完整。
12. 登录、计划编辑、开始训练、记录组数、训练完成、排行和账号弹层均无功能回归。

## 14. 交付与确认节点

1. 本规格确认后编写 implementation plan，明确组件拆分、依赖、文件范围和验证顺序。
2. implementation plan 确认后再开始修改代码。
3. 实现期间至少进行三轮真实浏览器视觉迭代：启动动画、桌面页面、手机页面。
4. 本地验收后先提供启动关键帧、桌面和手机效果供确认。
5. 用户确认视觉效果后，才使用中文提交信息 commit 并发布。
