# 训练日名称空值与占位规格

## 背景

休息日当前把“训练日”保存为默认名称。它看起来像用户已经填写的内容，又与右侧“训练日 / 休息日”状态重复，容易让用户误以为必须保留或修改这个系统名称。

本次把训练日名称改为真实空值，通过示例占位引导输入；业务状态仍由 `enabled` 控制。

## 目标

1. 新建或尚未命名的休息日不再显示“训练日”默认值。
2. 输入框空值时显示示例占位 `例如：全身`，不替用户写入内容。
3. 已启用但未命名的训练日，在只读位置统一显示 `未命名训练`，避免出现空白。
4. 兼容已有默认数据，不误删用户真正填写的训练名称。

## 数据语义

- `name === ""`：用户尚未命名。
- `enabled === false`：休息日，与名称是否为空无关。
- `enabled === true && name === ""`：有效训练日，但名称尚未填写；只读展示使用 `未命名训练`。
- 名称不是训练日成立的必要条件；训练日仍由 `enabled === true` 且至少存在一个动作决定。

## 输入框

- 训练名称输入框的真实 `value` 允许为空字符串。
- 空值时显示 `placeholder="例如：全身"`。
- 占位文字只提供命名示例，不写入 draft，也不随保存提交为真实名称。
- 输入框在训练日和休息日都可编辑，便于提前配置计划。
- 默认休息日的训练重点同样使用真实空值，占位显示 `例如：腿 + 胸 + 背`。

## 新计划默认值

- 周二、周四、周六、周日等默认休息日的名称由 `训练日` 改为空字符串。
- 默认训练日“全身 A / 全身 B / 全身 C”保持不变。
- 不修改默认动作和启用状态；默认休息日的训练重点从“自定义”改为空值。

## 旧数据兼容

不执行数据库批量迁移，只在读取计划时识别旧系统默认值。

仅同时满足以下条件时，把返回给前端的名称“训练日”和训练重点“自定义”分别规范化为空字符串：

1. `enabled === false`
2. 没有任何动作
3. `name === "训练日"`

以下情况必须保留原名称：

- 已启用的训练日名为“训练日”。
- 休息日保留了动作且名称为“训练日”。
- 任何其他用户填写的名称。

用户下次保存周计划时，规范化后的空名称自然写回数据库；不额外启动迁移任务。

## 保存接口

- 计划保存接口必须允许训练日名称为空字符串。
- 删除当前 `name || "训练日"` 的强制回填行为。
- 仍保留名称最大长度、字符清理和计划版本校验。
- 不改变训练日必须至少包含一个动作才能保存的现有规则。

## 只读展示回退

为避免空名称传播到界面和训练记录，统一使用：

```ts
const displayName = day.name.trim() || "未命名训练";
```

需要回退的位置：

- 计划页星期导航中的训练日名称。
- 计划页顶部固定栏中的训练日名称。
- 今日页本周计划列表。
- 今日训练开始时创建的训练快照 `planName`。

休息日仍显示“休息”，不显示 `未命名训练`。

## 与状态开关的关系

- 添加第一个动作自动切换为训练日，但不会自动填写名称。
- 训练日名称为空时，状态开关仍显示“训练日”。
- 切换为休息日不会清空已经填写的名称。
- 重新启用休息日保留的动作和名称时，原内容继续生效。

## 不在本次范围

- 不强制用户必须填写训练名称。
- 不调整 `enabled`、动作数量或今日计划的判断规则。
- 不新增数据库迁移文件。
- 不重新设计输入框位置、尺寸和顶部共享元素动画。

## 验收标准

1. 默认休息日名称输入框为空，并显示 `例如：全身`。
2. 默认休息日训练重点为空，并显示 `例如：腿 + 胸 + 背`。
3. 新计划不再把“训练日”或“自定义”写入默认休息日字段。
4. 旧的“休息日 + 无动作”系统默认名称和重点返回前端时显示为空。
5. 用户真实填写的名称和训练重点不会在其他状态下被清理。
6. 保存空名称后，重新加载仍保持空值，不会回填“训练日”。
7. 启用但未命名的训练日在导航、固定栏、今日页和训练快照中显示 `未命名训练`。
8. 休息日继续显示“休息”。
9. 训练日状态和动作规则不发生变化。
10. TypeScript、ESLint、生产构建、现有测试和 `git diff --check` 全部通过。
